# 分场景引导与偏好比较 V2

本轮修复了控制器与动画读取不同目标、静物仍依赖人脸显示、验证阶段提前呈现成功的问题。新偏好实验未通过准入，部署模型及关闭策略保持原状。

## 已落地的行为

- `GuidanceDecision.displayEvidence` 绑定控制器锁定的目标、当前主体和观测期限；显示不再从另一份渲染结果提取中心。
- `GuidancePresentation` 检查状态、动作、反馈与有效期。过期、异步状态不一致、恶化、无进展均隐藏方向并静态暂停；没有新帧也定时撤销旧显示。
- 人脸和对象使用同一呈现入口；移动提示改为“主体”。验证与 Ready 区分，绿闪、触觉和快门对齐态只跟随有效 Ready。
- Ready 使用实际目标容差，移除固定比例装饰圈。拍摄前仍由控制器二次确认依据。
- 人像、食物、静物、风景、城市及植物分别报告缺少的依据。没有可验证风景目标或完整植物范围时保留当前取景，不把三分法、边缘密度或场景分类直接变成移动命令。
- 摄影规则拒绝 NaN、非法主体框及无效九格统计，不能让异常数值绕过主体保护。

规则用于限定候选、保护已观测主体和解释拒绝，不保证三分构图一定比居中更美。当前仍无法预测取景之外的新背景、遮挡及透视。

## 连续执行验证

新增 JVM 回放覆盖人像、食物、静物的正确调整、反向调整、静止、缓存重复、主体丢失、就绪后变糊，共 18 条序列；另有自然风景、城市、植物无目标的 3 条序列。

21 条均满足预期终态。正确执行的几何误差由约 0.20 降至 0.06；反向执行与静止暂停；缓存及失去主体不会进入 Ready；就绪后变糊撤销。3 条无目标序列只记录终态，不计入逐帧覆盖率。

这些是可控屏幕坐标模拟，不是实拍效果或人类审美评价。机器可读摘要见 [回放结果](./evidence/scene-guidance-v2-replay.json)。原始逐帧记录位于项目本地 `local-output/scene-guidance-v2-2026-10-16/guidance-episodes.json`。

## 偏好模型实验结果

冻结 MobileNetV3，使用独立编码的真实候选裁剪及有效空间信息。新比较头为 605→64→1，比较 A/B 特征差，保留场景上下文，并进行反对称计算；相同画面差值为零。三个预先固定的正则候选只在验证集选型，拒绝阈值也只在验证集选择。教师对轻度 JPEG 变化判断不稳定的样本保留为不确定，不强制标成原图胜出。

排除先前质量／取景实验的验证、验收来源以及历史留组后，剩余 102 个来源簇：训练 52、验证 22、验收 28。编码器可能见过部分原图，因此不称为全系统独立测试。

| 项目 | 结果与解释 |
|---|---|
| 验证集稳定裁剪偏好 | 5 个原图簇、8 对；不足以校准拒绝阈值 |
| 验收集所有裁剪比较 | 34 对，包含教师不确定项 |
| 验收稳定裁剪偏好 | 3 个原图簇、4 对；不是 28 个有效偏好簇 |
| 按簇排序一致率 | 66.7%，保持原图基线同为 66.7%；置信区间下限 0 |
| 推荐覆盖率 | 0%，34 对全部拒绝推荐 |
| 明确缺陷排序 | 48 对均符合已知缺陷方向；不能代替审美验收 |
| 最终状态 | 未通过；未部署；验收只执行一次 |

失败原因包括有效来源不足、未优于保持基线、无法校准可靠推荐阈值。不能把缺陷检测成功包装成“模型能判断怎样更好看”。详见 [冻结验收输出](./evidence/pairwise-preference-v2-acceptance.json)，其中记录本地实验文件的哈希。

## 复现与存放

新实验入口：`ai/tools/build_template_db/run_pairwise_preference_v2.py --help`。需要已有项目本地教师、依赖和原始素材；参数包括来源 manifest、上一轮 quality/framing 目录、对象结构、编码器、vendor、deps 和输出目录。非空输出目录拒绝重跑，`--reuse-completed` 只校验已有结果及哈希。

本轮所有原图派生、特征、模型候选、完整冻结协议及日志位于 `local-output/scene-guidance-v2-2026-10-16/`。GitHub 只保存实现、测试和无原始图片的验收摘要。实验准入结果不自动写入手机资产，未来通过也需另行完成运行时接入及一致性验收。

回放由 `GuidanceEpisodeReplayTest` 执行；设置 JVM 属性 `guidance.episode.output` 可导出完整序列，再用 `ai/tools/build_template_db/summarize_guidance_episodes.py INPUT OUTPUT` 汇总。无此属性时 CI 只执行断言，不在工作树生成文件。

## 验证边界与后续重点

本地 JVM 使用 Android 类型桩验证引擎逻辑，完整 Android 编译及原生测试由 GitHub CI 执行。未连接物理手机，未声称中端机帧率、温升或动画设备验收通过。

下一阶段的瓶颈是新的、可靠且与既有验收隔离的同场景取景对，尤其是完整食物／静物结构，以及可验证的风景主体或地平线；不是继续用同一批失败样本反复调参。现阶段交付能力是有依据的单步指导和及时停止，审美改善仍未得到验证。
