# AI 推荐分析核心优化与验收

> 2026-10-15 阶段验收快照。后续多场景与执行反馈更新见 [2026-10-16 验收](./摄影规则与执行效果验证-2026-10-16.md)，当前部署规格见 [AI 接入说明](./09-AI接入包说明.md)。下文实验结果不因后续迭代改写。

本轮把参考检索接到可验证的单步摄影引导：同场景参考先经过人脸结构匹配，再生成小幅取景目标；实时观测确认用户是否朝目标改善，主体或传感器证据失效就撤销就绪。最终动作和拍摄就绪由同一个会话控制器决定。

现有 MobileNetV3-Small 512 维检索模型和 406 条图库向量保持不变。新增审美评分头已经实际训练、验收，但未达到预设门槛，因此正式包只发布禁用策略，不发布或运行候选权重。本轮不能宣称真实用户更喜欢最终照片。

## 已接入的核心行为

- 语义召回最多 32 张，结合真实脸框、脸部占比、画幅与裁切完整性筛选最多 8 张。兼容性描述参考是否适用，不是把当前主体越接近参考位置当成全部质量。
- 自动引导范围为唯一稳定人脸。多人、丢脸、缺少可信目标时保持；不以语义相似度、规则构图标签或单纯水平当成构图完成。
- 当前构图处于兼容范围时保留当前位置，不为套用三分法继续移动。动作期间锁定目标，同时持续检查其有效性和主体保护条件。
- 单步输出包含动作、目标、误差和执行反馈。连续两次有效观测恶化暂停；五秒无改善最多请求一次重新规划，避免左右反复催促。
- 人脸与 IMU 携带独立观测 ID 和单调采样时间。缓存可显示，但不能重复累计确认。进入就绪要求至少三个独立合格观测、跨度至少 750 ms；新的坏观测立即撤销就绪。
- 新观测才推进平滑；主体跟踪、镜头、预览裁切或旋转改变会失效旧目标。完成判定使用原始主体坐标，并用原始 IMU 否决被平滑掩盖的偏离。
- 继续保持单线程限频和忙时丢帧。推理推荐阶段超过 150 ms 后降低到一秒一次，十秒后再评估；人脸检测耗时单独计入几何阶段。这是运行时退让策略，不是已测得中端手机性能。

手机方向指令定义为沿屏幕方向的小幅平移。前摄的相机水平基向量和预览镜像同时参与坐标换算；不能只看到镜像标记就机械反转动作，也不能把平移文案改成未经验证的偏航旋转。

## 审美评分头的真实结果

教师为本地 OpenAI CLIP ViT-L/14 加作者发布的 improved-aesthetic-predictor。固定源码提交、权重 SHA、MIT/Apache-2.0 许可记录；图片仅在本地计算。许可记录不代替素材自身的授权。

学生输入固定为 512 维检索向量加 8 个统计/人脸特征，64 单元 ReLU 隐层，输出原始偏好分。检索编码器不更新，正式检索模型 SHA 仍是 `f7f76fa326e0bf089eeb98c7df6ca9ca8225719fa80d482919216dff7504a9cf`。

| 项目 | 实际结果 |
|---|---:|
| 训练实验源图 / 来源簇 | 404 / 341 |
| 原图、保脸裁剪及明确缺陷视图 | 1,086 |
| 全部监督对 | 1,203 |
| 固定训练候选数 | 3 |
| 导出权重 JSON 大小 | 178,774 bytes |
| 人像验收的有效来源簇 | 12，要求至少 30 |
| 稳定教师人像比较对 | 22，全部为明确缺陷 |
| 学生 / 简单结构基线对上述缺陷对的符合率 | 均为 100% |
| 有效的裁剪审美偏好比较对 | 0 |
| 正式审美评分状态 | **关闭** |

关闭原因是有效来源簇不足，以及没有优于简单基线。不能把上表的缺陷对符合率称作“审美准确率 100%”。实验的覆盖率表示非平局教师对上的学生分差覆盖，不是 App 拍摄建议覆盖率；该评分支路当前线上覆盖率为 0。

训练只在验证集选择三个预先固定的候选；验收只执行一次。已有 53 张历史测试没有用于这次调参，具有历史 holdout 关系的素材组从新实验中排除。当前编码器已见过部分原图，新的留组任务不能恢复全系统从未见过这些图的独立性。

候选裁剪接口能够单独编码真实裁剪图，最多两个、串行限频且缓存随主体和画面变化失效。但它仅为实验诊断，当前关闭；裁剪需要的变焦和视角变化没有被伪装成平移指令。原图裁剪后缩放与手机 224 图再次裁剪存在采样差异，检测器有效性也存在差异，缺少匹配证据时不准启用裁剪诊断，更不发布独立审美动作。

## 验证和复现

部署门禁重新校验结构与原图哈希、脸框范围、单人像与合成标记；质量启用需要实际指标通过，而不只信一个 `enabled` 布尔值。质量头形状、权重、有限数值、编码器、特征顺序及激活函数必须匹配。正式模型和历史评估绑定继续保留。

回归覆盖来源隔离、不可覆盖验收、错误权重与策略、镜像和旋转投影、重复缓存、坏 IMU、多人换人、目标失效、恶化及停滞。完整 Android 依赖由 GitHub Actions 验证；本地 JVM harness 的部分 Android、ONNX、ML Kit 使用桩，应与真实设备验证区别记录。本地原生引擎回归也执行了实际编译和运行。

本地最终结果：329 项 Python 测试通过（1 项可选 USearch 测试跳过）、233 项 JVM 测试通过、原生引擎回归通过、406 条正式资产与 15 条可用结构门禁通过。真实训练头的 Kotlin 数值探针与 Python 预期分数 `-0.5779706239700317` 的绝对差为 0；该探针直接测试本地候选，不修改正式禁用策略。
