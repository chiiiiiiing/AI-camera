# 自动主体引导修复（2026-10-20）

## 用户反馈与根因

上一版出现“只有水平辅助、约三秒后直接拍照”。根因不是 Git 合并冲突，而是以下实际执行分支：

- `CompositionSessionController.computeAction` 对没有主体/位置目标的画面，只要水平稳定就返回 Ready。
- 变焦准备窗口结束后，Ready 直接触发自动拍摄，因而视觉上像一个自动完成的倒计时。
- 物体检测仅在检索类别为 FOOD/STILL_LIFE 时运行；即使运行，类别白名单、多主体排除和 0.5 置信门槛仍会过滤掉大量检测。
- 主体目标和目标大小主要依赖少量参考图的结构标注，未命中时无法输出方向或变焦。

## 实现

1. 删除相机页的静物、风景、人像三个手动模式入口。显示“AI 自动识别”。
2. 大小足以作为主体的实时单人脸优先进入人像路径；非人像画面运行物体检测，不再以检索类别作为检测开关。
3. 物体候选以检测置信度、画面占比与靠近中心程度选择主主体。多个候选不再一律关闭引导。参考图匹配的严格筛选仍保留。
4. 优先使用兼容的参考结构；缺少参考结构时，使用真实检测框生成可达目标位置和有限倍率建议，明确标记 `live_face_rule` 或 `live_object_rule`。这是 AI 检测加取景规则，不宣称模型学会了最优审美。
5. 现场物体追踪允许 0.4 以上置信度，但必须连续至少两次检测成立。既有参考数据校验默认仍是 0.5。
6. 目标锁存，防止主体跨越中线时推荐点左右跳变；变焦输入使用真实主体与目标主体大小。
7. 如果主体检测较晚才提供尺寸，允许启动一次真实变焦准备；手动变焦始终让权。
8. 没有构图位置或可信姿态目标时，水平仪不能触发 Ready。Verifying 也不能借用 Ready 的轻微抖动宽限提前拍摄。
9. 检测/准备期间也显示真实检测框和目标，界面明确显示没有主体、主体丢失、位置建议或变焦状态。

## 验证及边界

`AdaptiveSubjectPlannerTest` 包含七项回归，覆盖真实检测框到目标的可达性、目标稳定、过期/多人拒绝、物体规则建议、方向到 Ready、长时间无目标不拍摄、确认中偏离不提前拍摄。

`AutomaticDetectionSmokeTest` 用仓库六张实际示例照片执行真实 ONNX NanoDet，共用 App 的像素预处理和检测解码，再把输出交给新的自动主体选择与规划器。甜品、花卉、蘑菇三个样本得到可用目标；建筑、街道、西瓜三个样本没有可用目标。未插入合成主体，也未对这些图片的语义分类正确率或审美提升作验证。

手机端的相机帧预处理已检查，实际创建 analysisBitmap、416px detectionBitmap 和坐标变换并送入 detectNative。桌面结果不能证明 Android 真机性能或相机现场识别准确率；本次无连接设备。

模型无法识别的画面会明确保持手动拍摄，不再用水平和时间流逝冒充 AI 构图完成。真实景深/三维机位规划及学习型最优构图仍不在本轮实现范围。

最终验证：新增七项规划回归与一项真实模型照片回放均通过；全量 334 项，327 项通过、7 项既有失败。剩余失败为 ExecutionQualityGuardTest 四项、RecommendationFeedbackTest 两项、MultiSceneSessionTest 一项，未删除或跳过断言。assembleDebug 与 lintDebug 通过，静态检查无错误、104 个警告。
