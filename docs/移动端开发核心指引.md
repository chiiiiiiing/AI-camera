## 1. 产品定位与分工

### 1.1 产品核心

一个 **AI 辅助构图的相机 App**。用户打开相机对准场景，App 实时分析画面内容，自动选择合适的构图策略（三分法、对称、引导线、留白等），通过**生动的辅助线**在取景器上直接引导用户调整手机位置和角度，拍出构图更好的照片。

### 1.2 团队分工

| 角色 | 谁 | 做什么 |
|------|-----|--------|
| AI 模型训练 | 队友 | 训练端侧模型：场景识别 → 构图策略选择 → 输出辅助线参数 |
| 产品经理 | 队友 | 定义功能范围、构图策略覆盖哪些场景、交互流程 |
| UI 设计 | 队友 | 辅助线视觉风格、App 整体界面设计、图标/动效规范 |
| **移动端工程** | **你** | **把以上所有东西在 Android 上跑通，做成一个能用的 App** |

### 1.3 你的工作边界

**你要做的：**
- Android 相机链路搭建（预览 / 拍照 / 相册保存）
- 实时帧采集 + 预处理 + 送入模型推理
- 解析模型输出 → 渲染辅助线（队友设计什么线你就画什么线）
- 性能优化（帧率 / 延迟 / 内存 / 发热）
- 打包、测试、上线

**你不用操心的：**
- 模型训练、数据集、模型结构选型
- 构图策略怎么定义（队友从 B 站/抖音的摄影教程里提炼）
- 辅助线长什么样、颜色、动效细节（队友出设计稿）
- 产品功能优先级排序

**你跟队友需要对齐的：**
- 模型输入/输出的格式约定（见 [附录 A](#附录a与你队友的协作接口)）
- 辅助线类型枚举 + 参数结构（队友定义类型，你实现渲染）
- UI 设计稿的交付形式（Figma / 标注稿 / 视频参考）

## 2. 整体管线架构

```
┌─────────────────────────────────────────────────────────┐
│                     Android 相机                         │
│                  CameraX + PreviewView                   │
└───────────────────────┬─────────────────────────────────┘
                        │ YUV/RAW 帧（30 FPS）
                        ▼
┌─────────────────────────────────────────────────────────┐
│                   帧采集 & 调度                          │
│   ImageAnalysis.Analyzer | 跳帧 | 只处理最新帧           │
└───────────────────────┬─────────────────────────────────┘
                        │ 选取帧（5–15 FPS）
                        ▼
┌─────────────────────────────────────────────────────────┐
│                   图像预处理                             │
│   YUV→RGB | resize | normalize | 格式转 Tensor           │
└───────────────────────┬─────────────────────────────────┘
                        │ Tensor
                        ▼
┌─────────────────────────────────────────────────────────┐
│                 AI 推理（队友的模型）                     │
│   LiteRT / MediaPipe | GPU Delegate | 后台线程           │
│                                                         │
│   输入：图像帧                                          │
│   输出：场景类型 + 构图策略 + 辅助线参数列表              │
└───────────────────────┬─────────────────────────────────┘
                        │ 辅助线参数 JSON/Protobuf
                        ▼
┌─────────────────────────────────────────────────────────┐
│                 辅助线渲染引擎                           │
│   解析模型输出 → 坐标映射 → Canvas/SurfaceView 绘制      │
│   绘制：网格线 | 箭头 | 目标点 | 水平仪 | 动态引导线      │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│                   PreviewView                            │
│        用户看到：相机画面 + 辅助线叠加                    │
└─────────────────────────────────────────────────────────┘
```

**关键点**：模型不是只输出"这是什么场景"，而是直接输出**"画什么辅助线 + 画在哪 + 怎么动"**。你的渲染引擎就是把这些参数变成屏幕上的像素。

### 3.5 关键注意事项

| 问题 | 处理 |
|------|------|
| 预览坐标 ≠ 照片坐标 | 拍照用全分辨率，预览是裁剪后的。辅助线坐标必须基于预览坐标系 |
| 前置摄像头镜像 | 预览时 CameraX 自动镜像，但 `ImageAnalysis` 的帧**不自动镜像**——如果你用分析帧画辅助线，需要手动翻转 X 坐标 |
| 旋转角度 | `imageProxy.imageInfo.rotationDegrees` 获取当前帧的旋转角度，用于坐标变换 |
| 权限流程 | 检查 → 请求 → 拒绝时引导去设置页 |
| 生命周期 | 相机绑定到 `ViewLifecycleOwner`（Fragment）或 `LifecycleOwner`（Activity） |

## 4. 模块二：实时帧处理管线

### 4.1 管线流程

```
ImageAnalysis 回调 (YUV_420_888, 30 FPS)
        │
        ▼
  [帧调度器]  跳帧策略：推理中则跳过，只取最新
        │
        ▼
  [预处理器]  YUV→RGB Bitmap | resize 到模型输入尺寸 | normalize
        │
        ▼
  [推理器]    喂入 LiteRT/MediaPipe | 后台线程
        │
        ▼
  [结果解析器] 提取辅助线参数 | 坐标映射 | 时序平滑
        │
        ▼
  [渲染回调]   post 到主线程 → 更新 Overlay
```

### 4.2 帧调度器（**最关键的部分**）

```kotlin
class FrameScheduler(
    private val inferenceExecutor: ExecutorService = Executors.newSingleThreadExecutor()
) : ImageAnalysis.Analyzer {

    @Volatile
    private var isProcessing = false

    override fun analyze(imageProxy: ImageProxy) {
        if (isProcessing) {
            imageProxy.close()  // ★ 丢弃，不排队
            return
        }
        isProcessing = true

        // 取出当前帧数据（在 imageProxy.close() 前完成）
        val bitmap = imageProxy.toBitmap()  // 或者直接传 YUV buffer
        val rotation = imageProxy.imageInfo.rotationDegrees

        inferenceExecutor.execute {
            try {
                val result = runInference(bitmap, rotation)
                // 结果回调到主线程
                mainHandler.post { onResult(result) }
            } finally {
                isProcessing = false
                imageProxy.close()
            }
        }
    }
}
```

### 4.3 ImageProxy → 模型输入

```kotlin
fun ImageProxy.preprocess(targetSize: Int): ByteBuffer {
    // 1. YUV → RGB Bitmap（或直接用 YUV plane 数据）
    val bitmap = this.toBitmap()
    
    // 2. Resize 到模型输入尺寸
    val resized = Bitmap.createScaledBitmap(bitmap, targetSize, targetSize, true)
    
    // 3. 转 Tensor（具体格式跟队友对齐）
    val byteBuffer = ByteBuffer.allocateDirect(4 * targetSize * targetSize * 3)
    byteBuffer.order(ByteOrder.nativeOrder())
    
    for (y in 0 until targetSize) {
        for (x in 0 until targetSize) {
            val pixel = resized.getPixel(x, y)
            byteBuffer.putFloat(Color.red(pixel) / 255.0f)
            byteBuffer.putFloat(Color.green(pixel) / 255.0f)
            byteBuffer.putFloat(Color.blue(pixel) / 255.0f)
        }
    }
    
    // 4. recycle 中间 Bitmap
    if (resized != bitmap) resized.recycle()
    
    return byteBuffer
}
```

### 4.4 帧处理关键点总结

| 问题 | 方案 |
|------|------|
| 跳帧 | `STRATEGY_KEEP_ONLY_LATEST` + 手动 `isProcessing` 标记 |
| 格式转换 | YUV_420_888 → RGB Bitmap → Float ByteBuffer |
| 旋转处理 | 读取 `rotationDegrees`，传入模型或预处理时旋转 |
| 镜像处理 | 前置摄像头时 X 坐标翻转 |
| 线程模型 | 推理在 `SingleThreadExecutor`，渲染在主线程 |
| 内存管理 | 用完 `imageProxy.close()`，中间 Bitmap 及时 recycle |

## 5. 模块三：AI 模型接入

> 模型是队友训练的。你的工作：**接进来、跑起来、稳定输出**。

### 5.1 模型做了什么（队友侧）

```
📷 相机画面
    │
    ▼
🧠 队友的模型:
    Step 1 — 场景识别：这是人像？风景？食物？建筑？街拍？
    Step 2 — 构图策略匹配：根据场景选策略（三分法/对称/引导线/框架构图...）
    Step 3 — 辅助线计算：输出该策略对应的辅助线坐标、类型、动画参数
    │
    ▼
📱 你的 App 收到: 辅助线参数列表 → 渲染到屏幕上
```

素材来源：B 站/抖音上有大量摄影构图教程（三分法、对称构图、引导线构图、留白、框架构图等等），队友会从中提炼构图策略并训练模型。

### 5.2 你的职责

1. **接收模型文件**：队友给你 `.tflite` 文件 + 输入/输出规格文档
2. **加载模型**：App 启动时异步加载，避免阻塞主线程
3. **预处理**：按队友指定的尺寸和归一化方式处理帧
4. **执行推理**：调用 LiteRT 推理 API
5. **解析输出**：把模型输出的 float 数组/Tensor 反序列化为辅助线参数
6. **结果平滑**：EMA 平滑避免辅助线抖动
7. **模型更新**：支持 OTA 下发新版模型

### 5.3 Android 推理方案选型

| 框架 | 适用场景 | 推荐度 |
|------|----------|--------|
| **LiteRT（原 TFLite）** | 队友提供 `.tflite` 模型 | ⭐⭐⭐ 首选 |
| **MediaPipe** | 需要预置的检测/分割/姿态能力 | ⭐⭐ |
| **ML Kit** | 用 Google 自带的人脸/物体检测 | ⭐ |
| **Google AI Edge SDK** | 新项目，整合上述能力 | ⭐⭐ |

> 首选 LiteRT：队友训模型 → 导出 `.tflite` → 你直接加载。最简单、最可控。

### 5.4 LiteRT 集成

```kotlin
// build.gradle.kts
dependencies {
    implementation("org.tensorflow:tensorflow-lite:2.16.1")
    implementation("org.tensorflow:tensorflow-lite-gpu:2.16.1")       // GPU 加速
    implementation("org.tensorflow:tensorflow-lite-support:2.16.1")   // 预处理工具
}

// 加载模型
class CompositionModel(context: Context) {
    private val interpreter: Interpreter
    
    init {
        val modelBuffer = FileUtil.loadMappedFile(context, "composition_model.tflite")
        val options = Interpreter.Options().apply {
            // 优先 GPU，fallback CPU
            try {
                addDelegate(GpuDelegate())
            } catch (e: Exception) {
                Log.w("Model", "GPU delegate not available, using CPU")
            }
            setNumThreads(4)
        }
        interpreter = Interpreter(modelBuffer, options)
    }
    
    fun predict(inputBuffer: ByteBuffer): ModelOutput {
        // 输出 buffer 大小跟队友对齐
        val outputBuffer = Array(1) { FloatArray(OUTPUT_SIZE) }
        interpreter.run(inputBuffer, outputBuffer)
        return parseOutput(outputBuffer[0])
    }
}
```

### 5.5 结果平滑（防抖）

```kotlin
class ResultSmoother(private val alpha: Float = 0.3f) {
    private var smoothed: ModelOutput? = null
    
    fun smooth(raw: ModelOutput): ModelOutput {
        if (smoothed == null) {
            smoothed = raw
            return raw
        }
        // EMA: new = alpha * raw + (1-alpha) * prev
        smoothed = smoothed!!.lerp(raw, alpha)
        return smoothed!!
    }
}
```

### 6.1 辅助线类型（预期）

| 类型 | 说明 | 渲染方式 |

```kotlin
class CompositionOverlayView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null
) : View(context, attrs) {
    
    private var guideLines: List<GuideLine> = emptyList()
    
    fun updateGuideLines(lines: List<GuideLine>) {
        guideLines = lines
        invalidate()  // 触发重绘
    }
    
    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        for (line in guideLines) {
            drawGuideLine(canvas, line)
        }

    private fun drawGuideLine(canvas: Canvas, line: GuideLine) {
        when (line.type) {
            GuideLineType.GRID -> drawGrid(canvas, line.params)
            GuideLineType.ARROW -> drawArrow(canvas, line.params)
            GuideLineType.TARGET_ZONE -> drawTargetZone(canvas, line.params)
            GuideLineType.HORIZON_LEVEL -> drawHorizonLevel(canvas, line.params)
            GuideLineType.BOUNDING_BOX -> drawBoundingBox(canvas, line.params)
            // ... 队友定义什么类型，这里就加什么 case
        }
    }
}
```

### 6.4 坐标映射

模型输出的坐标通常是归一化坐标（0.0–1.0），需要映射到 View 的实际像素：

```kotlin
// 模型输出坐标 → Overlay View 坐标
fun normalizeToView(modelX: Float, modelY: Float, viewWidth: Int, viewHeight: Int): PointF {
    // 注意：需要考虑旋转和镜像
    return PointF(
        modelX * viewWidth,
        modelY * viewHeight
    )
}
```

**特别注意前置摄像头的坐标镜像**：
```kotlin
fun normalizeToViewWithMirror(
    modelX: Float, modelY: Float,
    viewWidth: Int, viewHeight: Int,
    isFrontCamera: Boolean
): PointF {
    val x = if (isFrontCamera) (1.0f - modelX) * viewWidth else modelX * viewWidth
    return PointF(x, modelY * viewHeight)
}
```

```kotlin
    start()
}

// 箭头流动动画（沿引导线方向移动的虚线/光点）
val arrowFlowAnimator = ValueAnimator.ofFloat(0f, 1f).apply {
    duration = 1500
    repeatCount = ValueAnimator.INFINITE
    addUpdateListener { animation ->
        flowOffset = animation.animatedValue as Float
        invalidate()
    }
    start()
}
```

### 7.3 你不应该花时间的地方

- 辅助线的颜色、粗细、透明度 → 队友定
- 按钮位置、大小、图标 → 队友出设计稿
- 动画节奏 → 队友给参考
- 提示文案 → 队友写

你的重点是：**渲染性能**（不掉帧）、**坐标正确**（不偏移）、**状态同步**（不抖动）。

## 8. 模块六：性能优化

> AI 相机最容易翻车：卡顿、发热、耗电、延迟。

### 8.1 性能目标

| 指标 | 目标 |
|------|------|
| 预览帧率 | 30 FPS 稳定 |
| AI 推理帧率 | 5–15 FPS（按设备动态） |
| 推理延迟 | < 100ms（中高端）/ < 200ms（低端） |
| 辅助线渲染 | < 5ms（onDraw 耗时） |
| 冷启动到可拍摄 | < 800ms |
| 内存占用 | < 200MB（含模型） |

### 8.2 优化策略

| 类别 | 方案 |
|------|------|
| **帧率** | `STRATEGY_KEEP_ONLY_LATEST`，推理中跳过新帧 |
| **分辨率** | 推理用 224×224 / 320×320，拍照是全分辨率 |
| **推理加速** | GPU Delegate（首选）→ NNAPI Delegate → CPU 四线程 fallback |
| **模型量化** | 让队友导出 INT8 量化模型，体积和延迟都能大幅优化 |
| **Buffer 复用** | `ByteBuffer.allocateDirect` 一次，每帧复用填入数据 |
| **渲染** | Overlay View 只在数据变化时 `invalidate`，不用持续刷新 |
| **后台释放** | `onPause` / `onStop` 时停止推理、释放相机 |
| **低端机** | 降低推理频率 + 缩小输入尺寸 + 可能需要队友提供小模型 |
| **发热** | 监控 `ThermalStatus`，高温时降帧 |

### 8.3 设备分级

| 等级 | 典型设备 | 推理 FPS | 输入尺寸 | 模型 |
|------|----------|----------|----------|------|
| 高端 | S24 Ultra / 小米 14 Pro | 15 | 416×416 | 标准模型 |
| 中端 | Pixel 7 / 一加 11 | 10 | 320×320 | 标准模型 |
| 低端 | 中端国产千元机 | 5 | 224×224 | 量化小模型 |

### 8.4 性能埋点

```kotlin
// 至少监控这些指标
data class PerformanceMetrics(
    val previewFps: Float,          // 预览帧率
    val inferenceTimeMs: Long,      // 单次推理耗时
    val inferenceFps: Float,        // 实际推理帧率
    val memoryUsedMB: Float,        // 内存占用
    val droppedFrameCount: Int,     // 丢弃帧数
)
```

### 10.1 MVP 功能范围（V1.0）

|------|------|
| ✅ 相机预览 + 拍照 + 保存 | CameraX 基础链路 |
| ✅ 帧采集 + 模型推理 | ImageAnalysis + LiteRT |

## 附录A：与你（队友）的协作接口

> 你需要跟队友明确这些输入/输出约定。建议把这些写成一个独立的 `模型接口约定.md`。

### A.1 你需要从队友那里拿到什么

| 交付物 | 说明 |
|--------|------|
| **模型文件** | `.tflite` 文件 |
| **输入规格** | 尺寸（如 320×320）、通道数、像素格式（RGB/BGR）、归一化参数（mean/std） |
| **输出规格** | 输出 Tensor 的 shape 和每个维度的含义 |
| **输出 schema** | 辅助线参数的数据结构定义（JSON schema / Protobuf / 手写文档） |
| **辅助线类型枚举** | 支持哪些辅助线类型，每种类型的参数含义 |
| **模型版本号** | 用于后续更新管理 |

### A.2 输出 Schema 建议

建议让队友用这样的结构输出，你解析起来最方便：

```json
{
  "scene_type": "portrait",           // 场景类型
  "composition_strategy": "rule_of_thirds",  // 选中的构图策略
  "confidence": 0.92,                 // 置信度
  "guide_lines": [
    {
      "type": "rule_of_thirds_grid",  // 辅助线类型
      "visible": true,                // 是否显示
      "params": {                     // 具体参数（由队友定义）
        "vertical_lines": [0.333, 0.667],
        "horizontal_lines": [0.333, 0.667]
      }
    },
    {
      "type": "subject_box",
      "visible": true,
      "params": {
        "x": 0.35, "y": 0.4,
        "width": 0.3, "height": 0.5
      }
    },
    {
      "type": "target_zone",
      "visible": true,
      "params": {
        "center_x": 0.333,
        "center_y": 0.333,
        "radius": 0.15
      }
    },
    {
      "type": "horizon_level",
      "visible": true,
      "params": {
        "angle_degrees": -2.5
      }
    }
  ]
}
```

> **你只需要实现每种 type 的渲染逻辑，队友负责决定在每种场景下输出什么 type 和什么 params。**

### A.3 需要队友确认的问题清单

- [ ] 模型输入分辨率是多少？
- [ ] 输入是 RGB 还是 BGR？归一化 mean/std 是多少？
- [ ] 输出格式：直接 float 数组还是需要从 Tensor 里解析？
- [ ] 辅助线坐标是归一化坐标（0.0–1.0）还是像素坐标？
- [ ] 前置摄像头时坐标需要镜像吗？还是模型已经处理好了？
- [ ] 辅助线类型有哪几种？每种的具体参数含义？
- [ ] 动画效果有参考吗？（给视频/动图）
- [ ] UI 设计稿/标注稿什么时候能给？
- [ ] 辅助线的颜色、透明度、线宽有规范吗？
