# 多场景参考结构与自动评估

本轮为原有 406 张参考图补充可测量的颜色、明暗、边缘布局与真实物体检测。检索编码器、参考向量数量、旧 53 张检索测试和旧审美评分头验收集均未改动。原图、对照图和未筛选的实验记录留在项目本地。

## 实际覆盖与适用范围

| 场景 | 参考图 / 来源簇 | 自动规则可用物体目标 | AI 图像复核后物体目标 |
|---|---:|---:|---:|
| 自然风景 | 187 / 171 | 0 | 0 |
| 城市风景 | 23 / 18 | 0 | 0 |
| 食物静物 | 54 / 53 | 12 | 3 |
| 生活静物 | 76 / 46 | 3 | 0 |
| 植物静物 | 3 / 3 | 0 | 0 |
| 人像 | 63 / 52 | 0 | 0 |
| 合计 | 406 / 343 | 15 | 3 |

这里的零表示不生成本轮新增的物体移动目标，不表示删除语义参考或人像现有引导。风景与静物的明暗和边缘布局仍用于选择更相容的参考，RGB 网格另存用于诊断；布局不是地平线、分割结果或美感评分。植物只有三个来源簇，且花瓶／盆栽检测框不能证明覆盖全部花叶，因此不开放植物动作目标。

所有非人像结构来自固定 NanoDet 模型，先将完整 EXIF 正向图片变成 224 像素方形缩略图，再以匹配 Android 的双线性插值进入 416 像素检测输入。扩大输入不会恢复已经丢失的图像细节。模型 SHA-256 为 `4b82da9944b88577175ee23a459dce2e26e6e4be573def65b1055dc2d9720186`。

布局使用 `rgb224_rec601_grid3_forward_edges_v1`：在同一 224 输入上计算 Rec.601 明度与向右、向下差分的绝对值平均，再分成 3×3 网格；另保存 RGB 网格均值。整个过程只描述当前已见画面，不推断移动后背景或透视。

## 发现并隔离的误检测

对自动规则允许的全部 15 张参考逐张进行了 AI 图像复核，无需用户标注。发现了明确错误：贝壳被判为甜甜圈，翻开的书被判为蛋糕，玫瑰墙被判为披萨；另有检测只覆盖整盘菜中的西兰花、冰箱中的单瓶饮品、成组蛋糕中的一片等情况。

保留原始检测与自动结果，在独立的 `references-reviewed` 目录生成复核版本。12 张被排除为动作参考，仍可用于语义和布局匹配。三张接受记录为：

- `new_batch_01010`：主体明确的咖啡杯。
- `new_batch_01207`：完整披萨。
- `new_batch_01291`：主体明确的咖啡杯。

公开的 [15 条图像复核记录](evidence/multiscene-object-review-2026-10-15.jsonl) 逐条绑定模板 ID、图片 SHA-256 和检测模型 SHA-256，明确 `method=ai_visual_review`、`human_reviewed=false`。复核不是独立人工真值，也不是照片好看的证明。接受记录不能绕过原始边界、面积、类别、多人和多物体约束；缺少接受记录时不能开放新动作目标。

## 自动回归结果与边界

完整记录见 [机器可读评估报告](evidence/multiscene-reference-evaluation-2026-10-15.json)。

- 原始 15 个来源簇的镜像同类检测一致性为 11/15；AI 复核后三个簇为 3/3。错误检测也可能镜像一致，因此这个结果不作为准确率或 mAP。
- 对三个已审核参考原图额外回放更严格的手机端不确定性规则：主框以外置信度在 0.35～0.50、面积达到主框 35%、与主框 IoU 小于 0.60 的检测也会使动作暂停。两张通过、一张暂停：`new_batch_01010` 出现两个低置信度大杯框和一个人框，`new_batch_01207` 与 `new_batch_01291` 未出现该冲突。这只检查三张原图的一个观测门槛，未执行排除同源参考后的完整检索与就绪流程，不能当作真实查询覆盖率或端到端成功率。已审核参考数量与实时可指导数量分开报告。
- 复核后参考生成 12 个实际裁剪矩形候选，其中四个因切断已检测物体而被拒绝；被接受候选中，已检测主框保留不足 98% 的情况为零。该约束不能保证未检测物体不被切断。
- 71 张、63 个来源簇包含低调、高调、大面积暗部或亮部等风格反例，均未仅因全局明暗而被隔离。严重质量问题仍单独处理。
- 来源簇只计一次，同一原图的派生版本不会放大样本量。没有将这批已用于既有编码器的图片包装为新的独立泛化测试。
- 406 张原图的本地 CPU 检测耗时包含预处理与后处理，p50 约 155 ms、p90 约 173 ms；这是 Windows 本地环境测量，不能代表中端 Android 性能。
- 新增 Python 单元测试覆盖布局数值、边界与多人拒绝、错类主框、裁剪保护、风格反例、来源簇计数、复核身份绑定和实时低置信冲突暂停。检测覆盖率不等于检测正确率，更不等于审美改善。

## 手机推荐行为与交付

语义召回 32 张后，风景和静物以实际预览的 3×3 明暗／边缘布局、画幅兼容性重排到最多八张。布局比较扣除整体明度偏移；不会强迫居中画面变成三分法，也不会把倒影或背景水平边缘识别成真实地平线。场景需要连续观测共识，装饰人脸不能单独覆盖风景或静物分支。

物体分支仅在主体类别、边框、占比、跨帧重合与外观均稳定，参考属于同一场景且有绑定图片和模型哈希的接受记录时，给出小幅取景或保持建议。物体与人脸使用不同观测类型。检测框无法保证覆盖杯柄等未检出细节；多解、贴边、明显次物体、换物或陈旧观测时暂停建议。当前大多数生活静物不具备可靠物体目标，继续提供布局参考与端平，不伪造精确方向。

最终动作和 Ready 继续由同一个会话控制器产生。俯拍只有在新鲜 IMU 明确显示 roll 不可观测时跳过端平；缺少传感器不能冒充俯拍。独立观测累计、至少 750 ms 确认、两次恶化停止以及每个主体最多一次停滞重规划继续生效。风景单纯端平不能触发整体构图 Ready 或自动拍摄。曝光调整未启用，避免把白背景、夕阳或剪影风格当作必须修正的错误。

物体检测和检索共享 ONNX Runtime，在现有串行管线中运行，物体检测间隔至少一秒。检测耗时超过 250 ms 时丢弃该次结果并冷却五秒，过期整帧也不能建立目标。该策略不能中途取消原生调用，因此不等于承诺 250 ms 的绝对延迟上限。辅助模块缺失、模型身份不符或加载失败时回退到原检索能力。

部署资产增加 3,800,954 bytes 的检测模型，两个模型合计 8,701,202 bytes；原检索模型仍为 4,900,248 bytes。模型来自固定提交的 [OpenCV Zoo NanoDet](https://github.com/opencv/opencv_zoo/tree/47534e27c9851bb1128ccc0102f1145e27f23f98/models/object_detection_nanodet)，随包包含 Apache-2.0 许可及模型、输入输出与解码清单。没有启用先前未达标的审美评分头。

真实模型输出经过 Python／Kotlin／官方 OpenCV 解码器交叉检查：Kotlin 与 Python 最大坐标／置信度绝对差约 5.04×10⁻⁸，519,168 个输入数值的预处理差不超过 7.16×10⁻⁷。见 [数值报告](evidence/multiscene-detector-numerical-2026-10-15.json)。这些是桌面计算检查，不是 Android 原生执行或真机性能结果。

## 复现

以下命令从仓库根目录执行。输出目录必须为空；已有实验不会被覆盖。原始照片来自项目本地归档，不会上传。

```powershell
# 固定来源、模型 SHA 与许可证，已有文件通过核验后不重复下载。
& 'local-output/model-optimization-2026-10-14/.gpu-venv/Scripts/python.exe' `
  ai/tools/build_template_db/multiscene_detector.py `
  --download-dir local-output/multiscene-recommendation-2026-10-15/detector

& 'local-output/model-optimization-2026-10-14/.gpu-venv/Scripts/python.exe' `
  ai/tools/build_template_db/build_multiscene_references.py `
  --source-manifest local-output/core-recommendation-2026-10-15/data-rev2/source_manifest.jsonl `
  --model local-output/multiscene-recommendation-2026-10-15/detector/object_detection_nanodet_2022nov.onnx `
  --output local-output/multiscene-recommendation-2026-10-15/references-reproduced

& 'local-output/model-optimization-2026-10-14/.gpu-venv/Scripts/python.exe' `
  ai/tools/build_template_db/build_multiscene_references.py `
  --source-manifest local-output/core-recommendation-2026-10-15/data-rev2/source_manifest.jsonl `
  --model local-output/multiscene-recommendation-2026-10-15/detector/object_detection_nanodet_2022nov.onnx `
  --object-review docs/evidence/multiscene-object-review-2026-10-15.jsonl `
  --reuse-sidecar local-output/multiscene-recommendation-2026-10-15/references-reproduced/multi_scene_references.json `
  --output local-output/multiscene-recommendation-2026-10-15/references-reviewed-reproduced

# 在独立空目录中先校验完整模型/索引/侧包，再更新既有 Android 部署资产。
& 'local-output/model-optimization-2026-10-14/.gpu-venv/Scripts/python.exe' `
  ai/tools/package_multiscene_recommendation.py `
  --detector-dir local-output/multiscene-recommendation-2026-10-15/detector `
  --references local-output/multiscene-recommendation-2026-10-15/references-reviewed-reproduced/multi_scene_references.json `
  --staging local-output/multiscene-recommendation-2026-10-15/release-reproduced --deploy

$env:PYTHONPATH='ai/tools/build_template_db'
& 'local-output/model-optimization-2026-10-14/.gpu-venv/Scripts/python.exe' `
  -m unittest discover -s ai/tools/build_template_db/tests -p test_build_multiscene_references.py -v
```

每个输出目录包含 `multi_scene_references.json`、`coverage-report.json`、`automatic-evaluation.json`、`comparisons.html` 和原图／标注缩略图。原始运行的正式来源是 `local-output/multiscene-recommendation-2026-10-15/references-reviewed/`。公开报告不包含本地图片路径、原图或缩略图。
