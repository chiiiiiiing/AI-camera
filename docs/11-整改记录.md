## 九、2026-08-05 构图-拍摄工作流 v2 + 工程卫生

### 背景

旧拍摄流程：用户打开相机 → 辅助线始终叠加在取景器上（三分线、主体框、橙色十字目标区、旋转弧形等）→ 快门直接拍照 → 保存。

问题：
- 辅助线杂乱无章、无顺序，用户不知道看哪里
- 旋转指引（顺时针/逆时针）要求用户手动精准对齐，操作难度过高
- 拍摄键上方"变焦/水平/主体"提示文字无实际效果
- 引导线 UI 过时（橙色十字圆圈、旋转弧线等）

### v2 工作流设计

参考 CP 相机竞品，重新设计构图-拍摄工作流：

```
IDLE（干净预览，无任何叠加线）
  │ 用户按快门
  ▼
ANALYZING：自动缩到最广角 + "正在分析构图" 粉紫波纹动画（~1.5s）
  │ AI 内部确定构图框，不画任何引导线
  ▼
GUIDING：分析完成 → 冻结目标点坐标
  画面中央粉色圆点 ─ 虚线箭头 → 构图目标绿点（钉在屏幕不动）
  "将画面中心移至目标点"
  │ 用户平移手机，将粉点移向绿点
  ▼
READY：两点对齐 → 自动变焦到构图框 → 拍照 → 构图说明标签（停留 2.5s） → 回 IDLE
```

### 实现要点

#### 目标点冻结机制
核心问题：如果目标点从每帧 AI 输出实时更新，它会随画面一起移动，用户永远无法"追上"。
解决：`freezeCompositionTarget()` 在分析完成瞬间从当前帧提取目标坐标并冻结，钉在屏幕上不再变化。
用户平移手机 → 画面内容改变 → 但目标绿点不动 → 画面中心粉点向绿点靠近 → 对齐。

#### 删除的旧 UI
- 橙色十字圆圈（`GuideLineRenderer.drawTargetZone` 十字线移除，颜色从 `rgb(255,107,53)` 改为 BrandPink）
- 旋转引导弧线（`ComposeGuidanceOverlay` 的 AXIS_ROTATION / PLANAR_ROTATION → 路由至 NONE）
- 分步引导步骤指示器（`GuidanceStepIndicator`，①变焦/②水平/③主体）
- 底部提示文字（`GuidanceMessage`）
- IDLE 状态下所有叠加层不渲染（干净预览）

#### 对齐阈值放宽
`GuidanceStateMachineConfig`：nearThreshold 0.72→0.50，alignedThreshold 0.92→0.72。
降低操作难度，不要求用户精准对齐。

#### 旋转自动化
PITCH/YAW/ROLL 系列指令不再渲染视觉引导，旋转由系统在 READY 阶段自动完成。

### 工程卫生
- 新增 `CaptureWorkflowOverlay.kt` — 工作流叠加层（分析波纹 + 中心点指引 + 就绪反馈）
- 新增 `CaptureWorkflowState` 枚举：IDLE / ANALYZING / GUIDING / READY
- 新增 Room 数据库（`data/db/`）：`LocalUser` 实体 + `UserDao` + `AppDatabase`
- `AuthRepository` 重构：SharedPreferences JSON → Room DAO
- 集成同学交付图标（auth 输入框 PNG + 引导素材 10 张）
- 修复游客模式持久化（`createGuestSession()` 避免二次启动强制登录）
- 修复管线连接 deak（`CameraScreen` 移除 `!isRunning` 守卫，`connect()` 自带防重入）

**根因**：`ImuHorizonSensor` 使用 `atan2(-gx, -gy)` 公式，正立时输出 ~±180°、倒置时输出 ~0°。无 `isUpright` 检测，无圆周平滑。旧代码反复放宽阈值（2°→8°→12°）掩盖根因。

| `guidance/geometry/ImuHorizonSensor.kt` | 接入 HorizonMath + CircularAngleSmoother，暴露 `latestObservation()` |
