# 附录 A：与队友的协作接口

> 你需要跟队友明确这些输入/输出约定。**在队友回答之前，先开发不依赖这些信息的模块。**

---

## A.1 你需要从队友那里拿到什么

| 交付物 | 说明 | 优先级 |
|--------|------|--------|
| **模型文件** | `.tflite` 文件 | 🔴 阻塞（实际推理） |
| **输入规格** | 尺寸（如 320×320）、通道数（3）、像素格式（RGB/BGR）、归一化参数（mean/std） | 🔴 阻塞（实际推理） |
| **输出规格** | 输出 Tensor 的 shape 和每个维度的含义 | 🔴 阻塞（输出解析） |
| **输出 schema** | 辅助线参数的数据结构定义（JSON schema / Protobuf / 手写文档） | 🔴 阻塞（辅助线渲染） |
| **辅助线类型枚举** | 支持哪些辅助线类型，每种类型的参数含义 | 🟡 部分阻塞（框架可先搭） |
| **模型版本号** | 用于后续更新管理 | 🟢 不紧急 |
| **UI 设计稿** | 辅助线样式、App 整体 UI、动效参考 | 🟡 部分阻塞（框架可先搭） |

---

## A.2 输出 Schema 建议

建议让队友用这样的结构输出，你解析起来最方便：

```json
{
  "scene_type": "portrait",
  "composition_strategy": "rule_of_thirds",
  "confidence": 0.92,
  "guide_lines": [
    {
      "type": "rule_of_thirds_grid",
      "visible": true,
      "params": {
        "vertical_lines": [0.333, 0.667],
        "horizontal_lines": [0.333, 0.667]
      }
    },
    {
      "type": "subject_box",
      "visible": true,
      "params": {
        "x": 0.35,
        "y": 0.4,
        "width": 0.3,
        "height": 0.5
      }
    },
    {
      "type": "target_zone",
      "visible": true,
      "params": {
        "center_x": 0.333,
        "center_y": 0.333,
        "radius": 0.15
      }
    },
    {
      "type": "horizon_level",
      "visible": true,
      "params": {
        "angle_degrees": -2.5
      }
    }
  ]
}
```

> **你只需要实现每种 type 的渲染逻辑，队友负责决定在每种场景下输出什么 type 和什么 params。**

## A.3 需要队友确认的问题清单

- [ ] 模型输入分辨率是多少？
- [ ] 输入是 RGB 还是 BGR？归一化 mean/std 是多少？
- [ ] 输出格式：直接 float 数组还是需要从 Tensor 里解析？
- [ ] 辅助线坐标是归一化坐标（0.0–1.0）还是像素坐标？
- [ ] 前置摄像头时坐标需要镜像吗？还是模型已经处理好了？
- [ ] 辅助线类型有哪几种？每种的具体参数含义？
- [ ] 动画效果有参考吗？（给视频/动图）
- [ ] UI 设计稿/标注稿什么时候能给？
- [ ] 辅助线的颜色、透明度、线宽有规范吗？
