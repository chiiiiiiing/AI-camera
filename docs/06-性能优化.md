# 模块六：性能优化

> AI 相机最容易翻车：卡顿、发热、耗电、延迟。**不依赖队友，贯穿开发全程。**

---

## 6.1 性能目标

| 指标 | 目标 |
|------|------|
| 预览帧率 | 30 FPS 稳定 |
| AI 推理帧率 | 5–15 FPS（按设备动态） |
| 推理延迟 | < 100ms（中高端）/ < 200ms（低端） |
| 辅助线渲染 | < 5ms（单次 onDraw 耗时） |
| 冷启动到可拍摄 | < 800ms |
| 内存占用 | < 200MB（含模型） |
| CPU 占用 | 预览 + 推理 < 60%（中高端机） |

---

## 6.2 优化策略

| 类别 | 方案 |
|------|------|
| **帧率** | `STRATEGY_KEEP_ONLY_LATEST`，推理中跳过新帧 |
| **分辨率** | 推理用 224×224 / 320×320，拍照是全分辨率 |
| **推理加速** | GPU Delegate（首选）→ NNAPI Delegate → CPU 四线程 fallback |
| **模型量化** | 让队友导出 INT8 量化模型，体积和延迟都能大幅优化 |
| **Buffer 复用** | `ByteBuffer.allocateDirect` 一次，每帧 `clear()` 后复用填入数据 |
| **渲染** | Overlay View 只在数据变化时 `invalidate()`，不用持续刷新 |
| **后台释放** | `onPause` / `onStop` 时停止推理、释放相机 |
| **低端机** | 降低推理频率 + 缩小输入尺寸 + 可能需要队友提供小模型 |
| **发热** | 监控 `ThermalStatus`，高温时降帧 |

## 6.3 设备分级

| 等级 | 典型设备 | 推理 FPS | 输入尺寸 | 模型 |
|------|----------|----------|----------|------|
| 高端 | S24 Ultra / 小米 14 Pro | 15 | 416×416 | 标准模型 |
| 中端 | Pixel 7 / 一加 11 | 10 | 320×320 | 标准模型 |
| 低端 | 中端国产千元机 | 5 | 224×224 | 量化小模型 |

### 设备分级实现

```kotlin
object DeviceTier {
    enum class Tier { HIGH, MID, LOW }

    fun detect(): Tier {
        val totalRam = getTotalRam()
        val cpuCores = Runtime.getRuntime().availableProcessors()
        val sdkVersion = Build.VERSION.SDK_INT

        return when {
            totalRam >= 8L * 1024 * 1024 * 1024 && cpuCores >= 8 -> Tier.HIGH
            totalRam >= 4L * 1024 * 1024 * 1024 && cpuCores >= 4 -> Tier.MID
            else -> Tier.LOW
        }
    }

    fun getInferenceConfig(tier: Tier): InferenceConfig = when (tier) {
        Tier.HIGH -> InferenceConfig(fps = 15, inputSize = 416)
        Tier.MID  -> InferenceConfig(fps = 10, inputSize = 320)
        Tier.LOW  -> InferenceConfig(fps = 5,  inputSize = 224)
    }
}
```

## 6.4 性能埋点

```kotlin
// 至少监控这些指标
data class PerformanceMetrics(
    val previewFps: Float,          // 预览帧率
    val inferenceTimeMs: Long,      // 单次推理耗时
    val inferenceFps: Float,        // 实际推理帧率
    val memoryUsedMB: Float,        // 内存占用
    val droppedFrameCount: Int,     // 丢弃帧数
)

class PerformanceMonitor {
    private var inferenceCount = 0
    private var totalInferenceTime = 0L
    private var lastReportTime = SystemClock.elapsedRealtime()

    fun recordInference(timeMs: Long) {
        inferenceCount++
        totalInferenceTime += timeMs
    }

    fun getMetrics(): PerformanceMetrics {
        val elapsed = SystemClock.elapsedRealtime() - lastReportTime
        val inferenceFps = if (elapsed > 0) inferenceCount * 1000f / elapsed else 0f
        val avgTime = if (inferenceCount > 0) totalInferenceTime / inferenceCount else 0L
        val memInfo = Runtime.getRuntime().totalMemory() - Runtime.getRuntime().freeMemory()

        return PerformanceMetrics(
            inferenceFps = inferenceFps,
            inferenceTimeMs = avgTime,
            memoryUsedMB = memInfo / (1024f * 1024f),
            droppedFrameCount = 0,
            previewFps = 0f
        )
    }
}
```

    private val powerManager = context.getSystemService<PowerManager>()!!

    fun isThermalThrottled(): Boolean {
        return if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
            val status = powerManager.currentThermalStatus
            status >= PowerManager.THERMAL_STATUS_SEVERE
        } else {
            false
        }
    }

    fun onThermalStatusChanged(status: Int) {
        // THERMAL_STATUS_MODERATE → 降低推理帧率
        // THERMAL_STATUS_SEVERE → 停止推理，仅显示静态网格线
    }
}

## 6.6 常见坑与解决方案

| 坑 | 现象 | 方案 |
|----|------|------|
| 推理积压 | 画面引导明显延迟 | 只处理最新帧，推理中跳过新帧 |
| 内存泄漏 | 使用越久越卡 | 检查 `ImageProxy.close()` 和 Bitmap recycle |
| 主线程阻塞 | UI 卡顿 / 掉帧 | 确保推理在后台线程，渲染 onDraw < 5ms |
| 坐标错位 | 引导箭头位置不准 | 统一坐标映射函数，考虑镜像和旋转 |
| 发热 | 手机烫手、降频 | 降低推理帧率，后台时停止推理 |
| 模型加载慢 | 首次启动黑屏 | 异步加载 + 加载中显示静态网格线 |
