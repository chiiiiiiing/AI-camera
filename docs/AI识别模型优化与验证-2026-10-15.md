# AI 识别模型优化与验证（2026-10-15）

本次将推荐识别模型从随机初始化训练的 Tiny CNN，升级为官方预训练 MobileNetV3-Small 特征网络加 512 维检索头。真实 ONNX 验证中，相同 49 张查询对同一 579 张训练图库的同场景 Top5 命中从 44 张提高到 47 张。候选固定为 FP32；两次有限量化实验均未通过原有门槛，未采用失败量化产物。

本报告的“识别改善”指参考照片检索改善。同场景标签和教师检索接近程度不能证明拍出的照片更好看；当前没有人工摄影审美标签或实拍引导前后盲评数据。

## 模型与手机接口

| 项目 | 冻结候选 |
|---|---|
| 架构 | `mobilenet_v3_small_retrieval` |
| 预训练特征网络 | torchvision `MobileNet_V3_Small_Weights.IMAGENET1K_V1`，去掉分类器，冻结参数 |
| 总参数 | 1,222,432；特征网络 927,008，检索头 295,424 |
| 输入 | NCHW float32，RGB 224×224，沿用 App 的 `[-1,1]` 输入 |
| 图内预处理 | `[-1,1]` 转 `[0,1]`，再按 ImageNet mean/std 归一化 |
| 检索头 | 576 维池化特征先 L2 归一化，再做带偏置的 576→512 线性映射 |
| 输出 | 512 维 L2 单位向量；不能与旧模型向量混用 |
| ONNX | opset 17，支持动态 batch，实际 Android 使用 batch 1 |
| FP32 文件 | 4,900,248 bytes，约 4.67 MiB，小于原 5 MiB 模型文件预算 |
| ONNX SHA-256 | `f7f76fa326e0bf089eeb98c7df6ca9ca8225719fa80d482919216dff7504a9cf` |

官方权重来自 [torchvision MobileNetV3-Small](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html)，下载 URL 为 `https://download.pytorch.org/models/mobilenet_v3_small-047dcff4.pth`；实际 SHA-256 为 `047dcff4addef86ea5bc2eff13c9614dc11f47ab1160d0a71a25e7db994f4e1f`。实现的 BSD-3-Clause 许可不代替源图片的数据许可。完整来源、版本与 hash 写入 checkpoint 和实验 summary。

加载本地 checkpoint 不触发网络下载；只有显式迁移训练命令下载官方初始化权重，缓存固定在项目 `local-output/` 内。手机推理不需要联网。

## 有边界的训练与验证

沿用 2026-10-14 审计后的 train 579 / val 49 清单与缓存教师向量。只在 train 特征上拟合岭回归，不更新 ImageNet backbone，不用场景批量生成的构图、光线或美感标签训练辅助头。教师的 768→512 投影复用原 checkpoint 中由 train 拟合的投影，不使用 val 重拟合。

候选集合预先限定为正则系数 `0.01, 0.1, 1.0`，目标为平方误差和加 `λ × 权重平方和`，偏置不正则化。用 val 选择时要求以下四项均不低于原正式 INT8：macro recall@1、macro recall@5、micro recall@5、teacher Top5 重合率；通过后优先选教师 Top5 重合率最高者。三个候选均通过，最终选择 `λ=0.1`。该过程不读取 test 图片。

| λ | macro R@1 | macro R@5 | micro R@5 | teacher Top5 重合率 |
|---|---:|---:|---:|---:|
| 0.01 | 60.00% | 64.81% | 93.88% | 36.73% |
| **0.1** | **59.27%** | **66.67%** | **95.92%** | **39.59%** |
| 1.0 | 59.66% | 66.67% | 95.92% | 35.10% |

最终重新运行 ONNX Runtime 1.19.2，三个模型分别独立生成 train 图库和 val 查询向量，未复用旧 embedding：

| 模型 | micro R@1 | micro R@5 | macro R@1 | macro R@5 | teacher Top5 重合率 |
|---|---:|---:|---:|---:|---:|
| 原正式 Tiny INT8 | 75.51%（37/49） | 89.80%（44/49） | 52.60% | 63.37% | 21.22% |
| **新 MobileNetV3 FP32** | **83.67%（41/49）** | **95.92%（47/49）** | **59.27%** | **66.67%** | **39.59%** |
| 新默认量化版本，已拒绝 | 38.78%（19/49） | 83.67%（41/49） | 25.33% | 56.96% | 8.57% |

R@K 是“前 K 个参考中至少有一张同场景”的比例，不是构图正确率。val 中植物、城市各只有 1 张，44/49 的来源组未知；已知来源组排除了交叉，但未知来源及近重复问题尚不能证明完全独立。原 Tiny INT8 的历史校准接触过部分 holdout，它是产品对照，不是干净的泛化基线。

独立重跑 PyTorch checkpoint 与导出 ONNX 的 49 张 val：平均同图余弦 `0.999999999996`、最低 `0.999999999989`、最大绝对误差 `1.416e-6`，通过 `min cosine ≥ 0.99999` 和 `max abs ≤ 1e-5` 的导出一致性检查。这是数值校验，不代替上表检索质量测量。

## 量化拒绝与诊断

两次量化使用同一批 train-only 分层 128 张：人像 25、食物 25、生活静物 26、自然风景 26、城市 23、植物 3；seed `20260718`。独立 val 49 图检查，门槛始终为最低余弦 0.95、平均余弦 0.98、单位范数误差不超过 0.02。

| 变体 | 量化算子 | bytes | 平均余弦 | 最低余弦 | 结果 |
|---|---|---:|---:|---:|---|
| 默认 QDQ | 52 Conv + 1 Gemm | 1,539,476 | 0.131455 | −0.251231 | 拒绝 |
| `mixed_conv_int8` | 52 Conv；检索头保持 FP32 | 2,416,079 | 0.131195 | −0.258233 | 拒绝 |

原默认策略本来就只对 Conv/Gemm/MatMul 加 QDQ；输入仿射变换、SE Mul、特征与输出 L2 均已保持浮点，不是把全部算子改成 QOperator。第二次试验仅有针对性地将检索头排除量化，没有降低门槛或继续扫参数。

诊断在 4 个 Conv 的 19 个通道定位到 bias 转 int32 溢出；偏置尺度最小约 `1.13e-19`，源网络有 27 个近零权重通道，没有精确零尺度。bias/scale 超出 int32 范围可解释日志中的 cast warning，但尚不能将全部检索损失归因于这一项。两次失败量化均只留作本地证据。

## 性能测量范围

同一 Windows 开发机、ONNX Runtime CPU、2 个 intra-op 线程、1 个 inter-op 线程、batch 1、预热 5 次后测量 50 次：

| 模型 | p50 | p90 |
|---|---:|---:|
| 原 Tiny INT8 | 3.193 ms | 3.252 ms |
| 新 MobileNetV3 FP32 | 3.158 ms | 3.213 ms |
| 失败的新默认量化版本 | 3.774 ms | 3.836 ms |

测量仅覆盖桌面 CPU `session.run`，不含预处理、相机链路、Android 算子后端及热降频；近似耗时不能说明手机上同速。5 MiB 是模型文件预算，也不是运行时峰值内存。中端 Android 的持续预览延迟、内存、功耗和发热仍需真机验收。

## 冻结后的测试与最终图库

冻结记录：`local-output/model-recognition-2026-10-15/frozen-selection.json`。`evaluate_frozen_retrieval.py` 先校验候选和基线模型 SHA，再读取 test；拒绝覆盖已有报告，同一候选每个模型各自重建 train 图库。四指标门槛失败时退出码为 2，不触发新的训练搜索。

固定 `λ=0.1`、FP32 模型 hash 后，以 train 579 张为图库，实际执行 53 张 test 的一次对照。四项总指标门槛通过，未据此继续调参：

| 模型 | micro R@1 | micro R@5 | macro R@1 | macro R@5 | teacher Top5 重合率 |
|---|---:|---:|---:|---:|---:|
| 原 Tiny INT8 | 71.70%（38/53） | 84.91%（45/53） | 51.30% | 64.52% | 19.62% |
| 冻结 MobileNetV3 FP32 | **86.79%（46/53）** | **88.68%（47/53）** | **63.89%** | **65.28%** | **45.66%** |

整体改善没有覆盖每个场景。生活静物 Top5 从 **6/6 降至 4/6**；食物 Top1 从 11/12 降至 10/12，Top5 保持 11/12。植物仅 1 个查询，仍为 0/1；城市只有 3 个查询，Top5 仍为 1/3。人像 Top5 从 6/9 提至 9/9，自然风景从 21/22 提至 22/22。后续改进需要新的数据与独立评估，不能利用这批 test 再挑模型。

test 的 52/53 来源组未知，train 的未知组为 365/579；此前近重复审计还发现 1 对 train/test 感知近重复候选。精确 ID/hash 和已知来源组隔离通过，不足以证明完全独立泛化；旧 INT8 历史校准接触过 holdout 的限制也继续保留。

逐页实际查看全部 579 张 train 图片，401 张通过单图内容检查，178 张因教程、拼图、UI、方向或内容问题暂不进入直接参考库。另从 3 张拼图恢复 6 张单图，并通过 ImageGen 去除 1 张食物图的教学叠加，恢复结果均逐张复看。原图保留，AI 修复另存提示词与 synthetic 标记，不作为真实拍摄效果证据。

最终正式图库 **408 条**，全部用新模型重新编码：人像 64、食物 54、生活静物 76、自然风景 188、植物 3、城市 23。模型部署名为 `student_model.onnx`，manifest 使用 `deployment_onnx` 绑定实际 hash；旧模型和完整旧索引留在项目内实验备份。Android 缓存版本升级为 `v10-reviewed-recognition-1`，更新后重新复制配套模型及索引。

同一组 49 张 val 查询在最终 408 条图库上的 Top1 为 41/49、Top5 为 **48/49**，macro Top5 为 83.33%。这是改变图库后的部署诊断，与上面的固定 579 图库模型对照分开报告；不能把图库变化带来的增益全归因于模型。库内排除自身的 Top5 同场景为 96.32%，仅作索引一致性诊断。

发布门禁核对模型字节/hash、输入输出契约、408 行向量/metadata/keys 对齐与审阅来源，重算库内指标，并校验 `model_evaluation.json` 文件哈希、冻结候选哈希、未在 test 拟合/选模及四项实际非回退指标。删除新 profile 字段不能退回旧的 95% 库内门槛。408 条 metadata 通过 JSON Schema 与领域校验，不携带本机原图路径。

正式资源保留 `model_selection.json` 与 `model_evaluation.json`。已验证 Git 暂存区里的实际模型、评估报告和冻结记录字节哈希，避免 Windows CRLF 转 Git LF 后校验失败。最终本地 Python 全量 286 项测试通过（1 项可选 USearch 依赖测试跳过），JVM harness 214 项通过，CameraManager/IMU 的真实 API 编译通过。harness 对部分外部 API 使用桩；正式 Gradle/依赖及 C++ 检查由 [PR #3 的 GitHub Actions](https://github.com/chiiiiiiing/AI-camera/pull/3/checks) 执行。

另外实际逐张查看候选人像，合计记录 **8 个**近似脸框中心及 EXIF 直立宽高比；只在可比视口、足够相似且真实人脸检测有效时提供目标。主体检测、参考坐标与手机动作使用同一显示视口，修正移动方向、横竖屏 roll 方向及错误 Ready 状态。规则生成的构图、光线、拍摄距离在 Android 加载边界降为 unknown，不参与相应重排/滤镜/变焦证据。未验证的 pitch/yaw、通用脸高和猜测主体目标不自动生成。

参考库的视觉审阅、恢复拼图/教程/截图及人脸锚点属于另一个质量环节。`candidate_clean` 仅表示适合单图参考，不是人工美感真值；生成式修复和裁剪必须保留父图关系、来源组与复核记录。
