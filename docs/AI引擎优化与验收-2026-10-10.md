# AI 引擎优化与验收（2026-10-10）

目标：中端 Android 优先、端侧离线。在当前主分支 `fc267e5` 的根目录 `aicamera-app/` 上整合优化，保留已有拍摄、滤镜及俯仰/偏航交互。本次没有重新训练或替换 V9 权重，也没有发布 APK。

## 实施内容

| 部分 | 结果 |
|---|---|
| 模型调度 | 默认 500ms 模型采样，缓存基础推荐；每个被处理的帧仍更新几何，减少重复预处理和 ONNX 调用 |
| 推荐一致性 | 镜头、旋转、暂停恢复与模型热替换在推理线程清缓存；模板连续领先才切换，空结果不能复用旧推荐 |
| 相机资源 | 单消费者 Channel 管理 ImageProxy；暂停、取消、拒收时关闭帧；ML Kit 超时后保留 Bitmap 到异步任务真正结束 |
| 降级与初始化 | 校验/复制/加载异常完整收口；JNI 加载失败进入 FAILED；降级置信度和进度归零，保留手动拍照 |
| 构图判定 | 模板相似度与几何完成度分离；无效模型、缺真实人像或尚有移动/姿态指令时不能冒充达标，阻止错误自动流程 |
| 模型与索引契约 | 检查输入输出类型/形状、模型 hash、索引键序、维数、有限值与归一化；使用实际向量重算检索指标 |
| 稳健计算 | 极值向量使用 double 累加，拒绝 NaN/Inf/零向量；不为缺少主体位置的模板编造目标点 |
| 数据与缓存 | 模型、源图、预处理、向量 SHA-256 绑定缓存；无损 PNG 保持重读像素一致；蒸馏数据拒绝精确重复与混合 teacher 空间 |
| 性能观测 | 区分 modelFps 与几何 effectiveFps，统计模型+检索 p50/p90 与几何耗时 |
| C++ 原型 | 有界 top-k 堆减少排序开销；无 Catch2 也运行独立回归；当前未接入 App |
| 工程结构 | Android 使用唯一根目录入口，恢复 ai/tools 和 ai/engine 源码与测试，补 CI 与目录说明 |

500ms 是当前默认预算，没有宣称已实现按温度自动调频或固定 30fps。俯仰/偏航保留现有 IMU 流程，其输出不是从图像恢复的三维最佳机位。人脸检测也不是全身姿态估计。

## 模型效果口径

重新计算实际打包的 728 条 V9 int8 embedding，库内 leave-one-out top5 同场景命中率为 **96.15%**。每条查询排除自身，但仍是既有模板集合上的诊断，不能代表独立新照片准确率，也不能当作构图建议正确率或本次优化带来的精度提升。

旧 embedding 缺少生成模型 SHA-256 血缘。校验器会明确报告此缺口；它能验证当前模型文件、索引结构和实际检索指标，不能反向证明旧向量由当前模型生成。新流程开始记录来源，旧产物保持原样，计划重建时再补齐。

## 验证与限制

- 在新目录运行的 **38 项 Python 模型数据契约测试通过**；实际 728 条索引 gate 通过。
- 本地真实 V9、调度、几何、水平仪、状态机等实现同次 Kotlin 编译通过，**23 个测试类共 166 项 JVM 回归通过**。外部 Android/ONNX/ML Kit API 使用临时桩，结果不能代替完整 Android 构建。
- 最终集成重放验证了 null/未知模型输出立即撤销旧 Ready/ALIGNED，以及管线重启后帧序从 100 回到 1 时仍能消费失败观测；使用真实 RenderViewModel、SharedFlow 与控制器，Lifecycle 为临时桩。
- GitHub CI 已完成标准 Android `:app:testDebugUnitTest`（完整源码编译及单测）、打包资产 gate、CMake/CTest 与 Python 契约回归。[PR #3](https://github.com/chiiiiiiing/AI-camera/pull/3) 保留各提交的检查记录与 Android 测试报告；未执行真机 instrumentation 验收。
- 本机 Gradle 曾在 daemon 启动阶段报 `Unable to establish loopback connection`；本机没有连接手机，尚无端到端延迟、发热、耗电或拍摄效果证据。
- 提供的界面预览源码已作为参考；飞书正文未能读取，因此未宣称核对了完整飞书需求。

## 后续验收顺序

1. **中端真机稳定性。** 前后摄、四种旋转、前后台、人物进出、换场景与损坏模型降级；连续预览 30 分钟，确认无卡死、错误绿灯或自动拍摄。分别记录 ONNX-only、模型+检索和整帧 p50/p90，不能混用指标。
2. **独立效果集。** 用未进入训练或模板库的照片/短视频，按人物、地点、拍摄会话与近重复隔离。比较 teacher、FP32、int8 的分场景 top1/top5、方向错误率、无主体误引导率与模板切换次数。当前精确 hash 去重不覆盖近重复泄漏。
3. **重建交付包。** 在新来源契约下重新生成 embedding，并对模型、预处理、索引和 metadata 同批版本化；更新资产前保留可回退版本。
4. **按实测调整预算。** 再决定场景变化提前触发、热状态降频、非人像检测或换模型。当前数据量适合继续 exact search；增大模型或引入 ANN 应有真机收益证据。
