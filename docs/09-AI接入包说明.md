# 09-AI 接入包说明

> 给 Android App 队友的当前准交付文档。本文是 AI 接入的最新口径；旧文档中提到的“模型直接输出辅助线”或“只等 `.tflite`”已不是当前 v9 首发候选方案。
>
> 旧版“给 App 队友的交付清单回复”已删除；接入行为以源码中的 `V9Inference`、`V9EmbeddingRuntime` 为准，正式资产以第 2 节的 assets 目录和校验 gate 为准。

## 1. 当前结论

- 首发平台：Android。
- 推荐 runtime：ONNX Runtime Mobile。
- 当前模型候选：`tiny_cnn_v9_wide_topk_siglip2_512`。
- 模型做的事：输入相机帧，输出 512 维 L2 normalized embedding。
- App 要做的事：用 embedding 召回 top8，按规则重排后保留 top5，再把选中模板的 metadata 转成构图辅助线。
- 当前 V9 默认两次模型采样至少间隔 500ms；画面变化提前触发尚未实现，几何观测独立更新。
- 不要只信 top1：使用召回候选重排后的 top5，并做结果稳定。
- 队友旧清单里的 `ModelOutput` 可以作为 App UI 层对象保留，但它不是 v9 模型 tensor 的直接输出；应由 App 在 embedding 检索和模板 metadata 解析后组装。

当前仓库已经包含 Android Gradle/App 工程；本文保留接入协议、模型边界和验收标准，源码实现位于 `../aicamera-app/`。

## 2. 需要交给 App 的文件

正式交付包已随 Android 工程纳入版本管理，唯一资产入口为：

```text
aicamera-app/app/src/main/assets/ai/v9/
```

正式包必须包含以下 6 个文件，路径均相对此目录：

| 文件 | 用途 |
|---|---|
| `student_model.static_int8.onnx` | Android 首发候选模型，静态 int8 ONNX |
| `android_onnx_runtime_manifest.json` | ONNX runtime、输入输出、量化和校验信息 |
| `android_runtime_config.json` | App 接入配置：抽帧、重排、预算、索引路径 |
| `template_index/templates.embeddings.f32` | 当前 728 条 512 维模板 embedding |
| `template_index/templates.keys.json` | key 与 template_id 映射 |
| `template_index/templates.metadata.jsonl` | 模板的构图、光线、场景等信息 |

从仓库根目录运行正式资产 gate：

```sh
python -B ai/tools/validate_android_v9_assets.py --asset-root aicamera-app/app/src/main/assets/ai/v9
```

以此 assets 目录及 `validate_android_v9_assets.py` 的校验结果为准。gate 检查模型与索引契约并重算库内检索指标；该指标不是独立新照片泛化性能。运行时如需普通文件路径，可保持上述相对结构复制到 `filesDir/ai/v9/`。

`student_model.fp32.onnx`、`templates.usearch.idx`、`templates.usearch.json` 和 `templates.quality_report.md/json` 属于可选的历史诊断/评估产物，不是当前 App 正式包的必需文件。当前 App 使用向量精确检索。

旧说明中的 `tools/preprocessed/student_models/tiny_cnn_v9_wide_topk_siglip2_512/export/` 与 `tools/preprocessed/template_index.new_batch.student-tiny-cnn-v9-static-int8-onnx-512/` 是历史数据目录；本机资料已移至仓库外归档，不能当作当前仓库中可直接复制的文件或构建依赖。需要对照实验时，按 [仓库与本地目录说明](./仓库与本地目录说明.md) 查找历史资料并确认模型版本。

## 3. 模型规格

| 项 | 当前值 |
|---|---|
| runtime | ONNX Runtime Mobile |
| 输入 tensor | `image` |
| 输入 shape | `[1, 3, 224, 224]`，batch 可扩展 |
| 输入 dtype | float32 |
| 输入颜色 | RGB |
| 输入布局 | NCHW |
| 归一化 | `value = (rgb / 255.0 - 0.5) / 0.5` |
| 输出 tensor | `embedding` |
| 输出 shape | `[1, 512]` |
| 输出 dtype | float32 |
| 后处理 | 模型内已 L2 normalize，App 再做一次防御性归一化 |

注意：当前 v9 ONNX 只输出 embedding，不输出场景类别、构图策略或辅助线坐标。辅助线来自检索命中的模板 metadata，不是模型 tensor 直接吐出来的。

## 4. Android 依赖建议

建议从 ONNX Runtime Android 开始接入。本机导出/量化环境使用 `onnxruntime 1.19.2`，App 可先锁 1.19.x 起测；如果 Gradle 解析或设备兼容有问题，换同大版本可用版本后必须重跑 smoke test。

```kotlin
dependencies {
    implementation("com.microsoft.onnxruntime:onnxruntime-android:1.19.2")
}
```

如果团队最终改选 TFLite 或 NCNN，需要重新导出对应格式并重新做静态 int8 质量评估；不能直接把当前 TorchScript dynamic int8 当 Android 商用包。

## 5. 推理接入流程

相机帧处理顺序：

```text
ImageProxy
  -> 按 rotationDegrees 转正
  -> 转 RGB
  -> resize 224x224
  -> 写入 float32 NCHW buffer
  -> ONNX Runtime 推理
  -> 512 维 embedding
  -> L2 normalize
  -> template index topK 检索
  -> top8 召回 + 规则重排，保留 top5
  -> 选中模板 metadata
  -> 渲染辅助线/提示
```

ONNX Runtime 伪代码：

```kotlin
class V9EmbeddingRuntime(modelPath: String) : Closeable {
    private val env = OrtEnvironment.getEnvironment()
    private val session = env.createSession(
        modelPath,
        OrtSession.SessionOptions().apply {
            setIntraOpNumThreads(2)
        }
    )

    fun embed(input: FloatArray): FloatArray {
        val shape = longArrayOf(1, 3, 224, 224)
        OnnxTensor.createTensor(env, FloatBuffer.wrap(input), shape).use { tensor ->
            session.run(mapOf("image" to tensor)).use { result ->
                val raw = (result[0].value as Array<FloatArray>)[0]
                return l2Normalize(raw)
            }
        }
    }

    override fun close() {
        session.close()
    }
}
```

预处理伪代码：

```kotlin
fun bitmapToNchw224(bitmap: Bitmap): FloatArray {
    val resized = Bitmap.createScaledBitmap(bitmap, 224, 224, true)
    val out = FloatArray(3 * 224 * 224)
    val rBase = 0
    val gBase = 224 * 224
    val bBase = 2 * 224 * 224

    for (y in 0 until 224) {
        for (x in 0 until 224) {
            val pixel = resized.getPixel(x, y)
            val offset = y * 224 + x
            out[rBase + offset] = (Color.red(pixel) / 255.0f - 0.5f) / 0.5f
            out[gBase + offset] = (Color.green(pixel) / 255.0f - 0.5f) / 0.5f
            out[bBase + offset] = (Color.blue(pixel) / 255.0f - 0.5f) / 0.5f
        }
    }
    return out
}
```

## 6. 相机预览抽帧

不要在 30 FPS 预览上每帧跑 embedding。当前 V9 通过 `ModelOutputSampler` 默认至少间隔 500ms 采样模型，在间隔内复用基础推荐，几何观测独立更新。画面变化提前触发尚未实现。

下面保留原先按画面变化调度的后续设计，不代表当前实现，也不用于替代几何观测管线：

- `isEmbeddingRunning == true` 时直接 close 新帧。
- 距离上次 embedding 小于 500ms 时跳过。
- 500ms-1000ms 之间，只有画面变化明显或用户触发重新扫描才跑。
- 超过 1000ms 可跑一次刷新。
- 新结果没回来前，继续显示上一个稳定模板。

后续设计伪代码：

```kotlin
class EmbeddingFrameScheduler(
    private val minIntervalMs: Long = 500,
    private val maxIntervalMs: Long = 1000
) : ImageAnalysis.Analyzer {
    @Volatile private var running = false
    private var lastEmbeddingAt = 0L
    private var lastFrameSignature: FrameSignature? = null

    override fun analyze(image: ImageProxy) {
        val now = SystemClock.elapsedRealtime()
        val signature = cheapFrameSignature(image)
        val sceneChanged = lastFrameSignature?.isMeaningfullyDifferent(signature) ?: true
        val interval = now - lastEmbeddingAt

        val shouldRun = !running && (
            interval >= maxIntervalMs || (interval >= minIntervalMs && sceneChanged)
        )

        if (!shouldRun) {
            image.close()
            return
        }

        running = true
        lastEmbeddingAt = now
        lastFrameSignature = signature
        runOnInferenceThread(image)
    }
}
```

若后续实现 `cheapFrameSignature`，可评估低分辨率亮度直方图、中心区域均值或边缘强度等指标；当前仍以已实现的 500ms 最小模型采样间隔为准。

## 7. top8 召回与规则重排

当前 `search_top_k=8`、`display_top_k=5`：先召回 top8，再重排保留 top5，由稳定选择逻辑决定 UI 使用的模板。

基础分：embedding cosine similarity。

建议重排权重：

| 规则 | 分值 |
|---|---:|
| `photo_type` 匹配 | +0.08 |
| 高置信 `scene_category` 匹配 | +0.06 |
| 构图类型匹配 | +0.03 |
| 光线类型匹配 | +0.02 |
| `photo_type` 明显不匹配 | -0.08 |
| 高置信 `scene_category` 不匹配 | -0.04 |

如果 App 暂时没有独立场景分类器：

- `photo_type` 可先来自用户模式、入口 tab 或 topK metadata 多数投票。
- `scene_category` 不要硬过滤，只作为弱加分。
- top1/top2 cosine margin 小于 0.01 时，不要立即切模板；要求新候选连续 2-3 次稳定领先。

伪代码：

```kotlin
fun rerank(
    candidates: List<SearchHit>,
    context: SceneContext,
    previous: Template?
): List<TemplateScore> {
    return candidates.map { hit ->
        val meta = hit.template.metadata
        var score = hit.cosine
        if (meta.photoType == context.photoType) score += 0.08f else score -= 0.08f
        if (context.sceneConfidence >= 0.7f) {
            score += if (meta.sceneCategory == context.sceneCategory) 0.06f else -0.04f
        }
        if (meta.composition.type == context.preferredComposition) score += 0.03f
        if (meta.lighting.quality == context.lightingQuality) score += 0.02f
        TemplateScore(hit.template, score)
    }.sortedByDescending { it.score }.take(5).stabilizeAgainst(previous)
}
```

## 8. 从模板生成辅助线

`templates.metadata.jsonl` 里每行是一条模板。App 首先使用这些字段：

| 字段 | 用途 |
|---|---|
| `template_id` / `photo_id` | 唯一标识 |
| `photo_type` | portrait / landscape / still_life |
| `scene_category` | 更细场景 |
| `composition.type` | rule_of_thirds / centered / symmetry 等 |
| `composition.subject_position` | 主体位置建议 |
| `composition.horizon_position` | 地平线位置建议 |
| `composition.leading_lines` | 是否需要引导线提示 |
| `composition.negative_space` | 留白强度 |
| `lighting.*` | 光线提示 |
| `camera.*` | 机位、距离、横竖构图提示 |
| `visual_summary` | 可转成用户可读提示 |

第一版可以只实现几类稳定映射：

- `rule_of_thirds`：显示三分线和目标交点。
- `centered` / `symmetry`：显示中心线或对称轴。
- `horizon_position=lower_third/upper_third`：显示水平参考线。
- `leading_lines=true`：提示用户寻找画面中的延伸线，不强画具体线段。
- `negative_space=high`：提示保留留白区域。

更精确的主体框、引导线几何坐标需要 App 侧检测器、视觉算法或后续模型输出补充；当前 v9 embedding 模型不直接给坐标。

## 9. 质量和预算

离线质量：

| 版本 | top5 同场景 | top5 同类型 | 结论 |
|---|---:|---:|---|
| SigLIP2 teacher | 97.53% | 99.31% | 离线上限 |
| student v5 | 94.37% | 97.94% | 未达 95% 门槛 |
| student v9 FP32 | 96.57% | 98.49% | 当前最佳 FP32 |
| student v9 static int8 ONNX | 96.15% | 98.21% | Android 首发候选 |

端侧预算：

- 静态 int8 ONNX 大小：301,677 bytes，小于 5MB 目标。
- 单帧 embedding 延迟目标：p50 <= 80ms，p90 <= 150ms。
- 这两个延迟值必须在目标 Android 真机上实测；当前仓库只有 host 离线验证。

## 10. App 验收清单

- 模型和索引能从 assets 复制到 app-private files 目录。
- ONNX Runtime 能加载 `student_model.static_int8.onnx`。
- 单帧推理输出 shape 为 `[1,512]`。
- 输出 embedding L2 norm 约等于 1.0。
- 同一张测试图多次推理结果稳定。
- 搜索召回 top8，重排保留 top5，且 UI 使用稳定选择后的结果。
- 预览 30 FPS 不被推理阻塞。
- 默认 embedding 两次实际采样至少间隔 500ms；间隔内几何观测继续更新，不将画面变化提前触发当作已实现能力。
- 目标 Android 设备实测 p50 <= 80ms、p90 <= 150ms。
- 连续预览 10-30 分钟无明显内存增长、过热、卡死。
- 前后摄切换、旋转、后台恢复后推理链路正常。
