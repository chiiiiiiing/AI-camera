# AI 接入包说明

核对日期：2026-10-16。本文说明当前 Android 实际使用的模型与接口；不再沿用 Tiny INT8、728 条参考或模型直接输出引导指令的旧方案。训练与实验结论见[验收记录索引](./README.md)。

## 1. 当前运行链路

```text
共享预览 ViewPort
  → 裁剪、转正、前摄镜像
  → 224×224 RGB 检索输入
  → MobileNetV3-Small + 512 维检索头
  → 最多 32 张语义候选
  → 人脸／对象结构与场景布局筛选，最多 8 张
  → 稳定参考与有依据的构图目标
  → CompositionSessionController 单步动作及执行反馈
  → CaptureWorkflowOverlay
```

检测及画面质量另用同一视口的图像证据。NanoDet 使用等比例保留画幅的分析图和 letterbox，不能复用已拉成正方形的 224 检索输入冒充原画幅检测。

模型 tensor 输出只有 embedding，不直接输出中文指令、人体轮廓、地平线或审美概率。场景来自后续参考及布局判断；动作来自可验证结构、IMU、质量检查与会话控制器。

## 2. 检索模型接口

| 字段 | 当前规格 |
|---|---|
| 文件 | `student_model.onnx` |
| 架构／精度 | `mobilenet_v3_small_retrieval`，FP32；失败的 INT8 候选未采用 |
| 大小 | 4,900,248 bytes，约 4.67 MiB |
| Android runtime | `onnxruntime-android:1.19.2`，版本锁定于 Gradle version catalog |
| 输入 | 名称 `image`，单帧 `[1,3,224,224]`，float32、RGB、NCHW |
| 像素归一化 | `(rgb / 255.0 - 0.5) / 0.5` |
| 输出 | 名称 `embedding`，单帧 `[1,512]`，float32 |
| 后处理 | 模型内 L2 归一化，检索前再做防御性归一化 |
| 索引 | 406 条、512 维、float32；当前 Android 使用精确向量检索 |

模型内部已经处理预训练骨干需要的归一化转换，App 不要再额外应用 ImageNet mean/std。推理与评估需使用一致的真实预处理，不能只比较输出维度。

默认模型采样最小间隔 500ms，慢推理降级期间可提高至 1000ms；几何观测独立更新。配置中保留的“meaningful scene change”描述不表示通用画面变化提前触发调度已经实现。运行行为以 `ModelOutputSampler` 和 `V9Inference.minInferenceIntervalMs` 为准。

## 3. 部署资产

唯一正式入口：[Android V9 assets](../aicamera-app/app/src/main/assets/ai/v9/)。更新必须作为匹配的资产包进行，不能仅覆盖权重。

| 文件／目录 | 用途 |
|---|---|
| `student_model.onnx` | 正式检索编码器 |
| `android_onnx_runtime_manifest.json` | 架构、输入输出、精度、大小、hash、模型来源 |
| `android_runtime_config.json` | 模型与索引路径、采样、候选筛选、侧包绑定 |
| `template_index/templates.embeddings.f32` | 连续 float32 检索向量 |
| `template_index/templates.keys.json` | 行与模板 ID 对应关系 |
| `template_index/templates.metadata.jsonl` | 参考元数据；历史推断标签不是人工摄影标注 |
| `model_evaluation.json`、`model_selection.json` | 冻结评估与选型证据 |
| `reference_structures.json` | 绑定图片来源的参考结构 |
| `quality_policy.json` | 第一版可选审美头策略，当前禁用 |
| `object_detector.onnx`、`object_detector_manifest.json` | NanoDet 及输入、来源契约 |
| `LICENSE.object_detector.txt` | 检测器随包许可，不得当作无用文档移除 |
| `multi_scene_references.json` | 多场景布局及经筛选的对象参考 |
| `framing_preference_policy.json` | 相对取景头准入策略，当前禁用 |

NanoDet 3,800,954 bytes；与检索模型合计 8,701,202 bytes。5 MiB 是检索模型预算，不是整个资产包大小。目前未部署未准入评分头权重。

配置仍保留 `display_top_k=5` 等兼容字段；当前实际先召回 32，再做最多 8 张结构／场景筛选，不应把旧文档的“top8 召回、top5 输出”继续当作完整链路。具体展示由实际消费者决定。

## 5. 更换模型或图库的验收

从仓库根目录运行：

```sh
python -B ai/tools/validate_android_v9_assets.py --asset-root aicamera-app/app/src/main/assets/ai/v9
```

随后按[Android 开发与验证](./Android开发与验证.md)运行对应测试。校验重点：

- 模型、索引、元数据、结构及侧包数量、维度、hash 一致；图片处理版本能追溯。
- embedding 有限、维度正确、L2 范数合理；索引与模型使用同一特征空间。
- 留组数据划分、模型选型与冻结测试彼此分离；正式资产校验不能替代独立泛化测试。
- 主体丢失、证据过期、画质退化、目标切换会停止误导；AF/AE 返回后重新检查拍摄资格。
- 候选模型或评分头未达标时保留基线并禁用候选，不降低门槛刷同一验收集。

当前检索改善已做离线验证；“调整后人类觉得更美”和中端真机性能尚未完成验证。manifest 中 p50 ≤80ms、p90 ≤150ms 等数值是目标，不是实测结果。风景没有可靠语义地平线，人像框不等于全身轮廓，Pitch/Yaw 目标来源尚未接入。
