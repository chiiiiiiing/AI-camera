## 4. 当前设计的主要问题

### 4.1 相机构图辅助偏重

节点 `1:11` 和 `1:13` 使用粗、等距、完全不透明的横向虚线，横跨整个取景画面。它能说明旋转轴，但视觉重量高于主体，也容易呈现游戏 HUD。

改进：使用 `1 dp` 左右的渐隐轴线，中心略清晰、两端消失；轴线保持稳定，只承担“旋转轴”语义。

### 4.2 旋转符号空间关系不充分

海滩状态中的箭头接近二维回转符号，俯仰、偏航和纸面内旋转之间缺乏统一的三维表达规则。

改进：使用压缩椭圆弧表达透视，远侧降低透明度，近侧略清晰；箭头沿弧线切线方向构成连续几何体。

### 4.3 人物目标轮廓抢占主体

节点 `1:15` 和 `1:17` 的白色粗虚线直接压在人像边缘上，容易遮挡面部、衣服边界和肢体判断；目标态与对齐态主要依赖轮廓位置变化，完成反馈不够集中。

改进：轮廓线减细、降低不透明度并避让面部；目标态使用开放虚线轮廓，对齐态减少动画并收束为局部完成标记。

### 4.4 对齐反馈尺度过小

节点 `1:9` 的完成标记很小，在复杂取景背景上可能难以被首次使用者发现。

改进：保留克制的小型标记，但增加一次有限的弧线收束和稳定色过渡；不持续闪烁、不增加大面积遮罩。

### 4.5 缺少简短动作语义

相机画板主要靠图形表达，没有为首次使用者提供稳定的一行短提示。对于二维箭头难以区分的俯仰和偏航，学习成本偏高。

改进：只显示当前优先动作的一行短文案，例如“轻轻向上抬起”，放在主体安全区之外；接近目标后自动弱化。

### 4.6 相机上下控制区需要适配真实系统 Insets

Figma 使用固定 `412 × 917` 画板和静态系统栏。直接照搬固定高度会在真实设备上造成状态栏、手势区或小屏裁切。

改进：视觉比例跟随 Figma，布局使用 Compose WindowInsets；快门触控区至少 `80 dp`，其他图标至少 `48 dp`。

### 4.7 认证页可读性与表单反馈不足

登录和注册页整体视觉干净，但浅色占位文字与粉紫背景的对比偏弱；输入线、错误、焦点和禁用状态在静态稿中没有形成完整体系。

改进：保留底线输入外观，提高正文对比度；使用焦点线颜色、错误短文案和按钮状态共同表达，不改为默认 Material TextField 卡片。

### 4.8 社区与主页存在演示内容边界

Figma 包含用户、粉丝、作品、点赞和评论，但当前没有后端协议。若直接实现网络交互会虚构产品能力，也会引入不必要的隐私风险。

改进：本轮只使用明确隔离的本地演示 Repository，不收集、持久化或上传账号和社区数据。

## 5. 统一视觉层级

相机页采用五层结构：

1. 真实 CameraX 预览。
2. 低干扰目标框、构图参考和静态虚轴。
3. 当前唯一的方向箭头或透视弧。
4. 一行简短指导、进度或完成反馈。
5. 顶部和底部相机控制。

同一时刻只允许一个主引导。其他误差不同时争夺注意力；主引导由状态模型确定，Canvas 组件不自行读取相机或模型对象。

## 6. 构图引导规范

### 虚轴线

- `1 dp` 左右细线，必要时使用极轻的反差描边。
- 中心清晰、两端渐隐，避免机械等距粗虚线。
- 保持稳定，不参与箭头循环位移。
- 有主体边界时降低面部和主体核心区域的局部透明度。

### 透视椭圆弧

- Pitch 使用水平轴配合纵向压缩椭圆弧。
- Yaw 使用垂直轴配合横向压缩椭圆弧。
- Roll 围绕光轴中心绘制压缩椭圆或局部弧。
- 远侧弧降低透明度，近侧弧略提高清晰度。
- 弧线和箭头共享 Path 与线宽，不使用独立粗三角贴片。

### 平移箭头

- 左右和上下平移使用短线性轨迹，不复用旋转弧。
- 目标框稳定，箭头在接近目标时缩短行程并降低速度。

### 人物轮廓

- 轮廓不是固定 SVG 或固定 Path；AI 每帧输出一个或多个归一化点集，Compose 按当前预览尺寸实时重建 Path。
- AI 点坐标使用 `0..1` 归一化空间；非有限坐标丢弃，越界坐标夹紧，少于两个有效点的轮廓不绘制。
- Debug 只使用明确标注的逐帧生成样本验证样式和状态切换；生产 `Flow<GuidanceSample>` 存在时完全替代 Debug 样本。
- Figma `1:15` / `1:17` 只作为虚线粗细、透明度、目标态和对齐态的视觉参考，不作为生产人物形状数据。
- 不将 Debug 轮廓伪装成已经接入的人体关键点模型。

## 7. 状态与动效表

| 状态 | 图形差异 | 动画含义 |
| --- | --- | --- |
| 未检测到主体 | 中性低透明度目标框 | 低频呼吸，表示等待主体 |
| 正在分析 | 稳定参考框与局部高亮 | 单次或低频扫过，表示正在计算 |
| 左右移动 | 水平短箭头 | 沿目标方向小范围循环 |
| 上下移动 | 垂直短箭头 | 沿目标方向小范围循环 |
| 调整俯仰 | 水平虚轴与纵向透视弧 | 高亮沿弧线缓慢流动 |
| 调整偏航 | 垂直虚轴与横向透视弧 | 高亮沿弧线缓慢流动 |
| 顺/逆时针旋转 | 光轴周围局部椭圆弧 | 箭头朝向和运动方向共同区分 |
| 错误方向 | 暖色与反向端点 | 一次短回弹，不抖动画面 |
| 接近目标 | 更短、更稳定的主引导 | 幅度约降至 45%，周期延长 |
| 已对齐 | 收束的完成图形 | 单次收束后静止并降低干扰 |
| 快门按下 | 快门内圆与外环 | 有限按压缩放 |
| 拍摄成功 | 短白闪与缩略图更新 | 单次反馈，不阻断预览 |
| 权限未开启 | 独立品牌权限页 | 不使用循环动效 |
| 初始化/分析失败 | 可重试或非阻断提示 | 单次出现，保留可用功能 |

相机页最多存在一个持续 Guidance 动画时钟。状态改变或 Composable 离开后必须取消；其他动画均为有限动画，并尊重系统动画缩放。

## 8. 视觉令牌基线

### 品牌

- 启动、认证和主页背景：柔和粉—淡紫—淡蓝渐变。
- 主标题与主按钮：Figma 实测深紫 `#4B3A62`。
- 快门：Figma 实测浅粉 `#F4B6C2` 内圆、白色外环、黑色控制背景。
- Logo 节点：`1:28`；可见渐变从浅粉 `#FFCCF2` 附近过渡到紫色 `#977DFF` 附近。

### 字体

- 中文品牌“帧好”：Noto Sans CJK SC，约 `36 sp`、Bold。
- 英文 `GenWow`：Roboto Medium，`16 sp`，约 `6 sp` 字距。
- 登录/注册标题：约 `26 sp`。
- 表单和正文：约 `14 sp`。
- 辅助信息：约 `11–12 sp`。
- 项目未包含合法字体文件时使用系统 Sans Serif，并把字体替代记录为有意偏差。

### 间距与形状

- 基础间距：`4 dp`；常用 `8/12/16/24 dp`。
- 图标触控目标至少 `48 × 48 dp`。
- 快门触控目标至少 `80 × 80 dp`。
- 小型提示圆角 `12–16 dp`，按钮和胶囊按 Figma 比例实现。
- 不使用厚重阴影、廉价霓虹或高成本实时模糊。

## 9. 必要推断和有意偏差

- Figma 相机画板中的照片只作为 Overlay 和控制区的视觉参考，生产预览始终使用真实 CameraX。
- Figma 的粗虚轴和二维箭头会按产品要求改为渐隐轴、透视弧和几何箭头，这是有意的视觉优化。
- Figma 没有给出真实 AI 分析协议；现有 `GuidanceAnalyzer` 保留可替换边界，Debug 状态不声称是真实模型推理。
- Figma 没有认证、验证码和社区后端协议；这些页面只实现本地演示数据与 UI 状态。
- Figma 固定系统栏不会硬编码到页面，真实实现使用系统 Insets。

## 10. 隐私与素材策略

- Figma 渲染 PNG、模拟器截图和 APK 仅保存在本地工作区或临时目录。
- 不把完整 Figma 画板作为应用资源打包；只导出实现必需的 Logo、图标和内容图片。
- 不记录或持久化登录页输入的账号与密码。
- 不提交 `local.properties`、keystore、Token、Gradle 缓存、构建缓存或截图。
- 不推送 GitHub、不创建公开 Release；生产签名仍由产品方单独安全配置。

Figma 读取、画板结构、字体层级、正式 Logo 和关键视觉方向均已确认，设计实现不再受“设计稿不可访问”阻塞。下一阶段可以在不触碰相机业务逻辑的前提下建立品牌颜色、渐变、字体、形状和 Motion Token。
