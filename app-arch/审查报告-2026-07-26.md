## 一、App 定位

实时构图辅助相机：相机预览时端侧 AI 分析画面 → 检索构图模板库 → 在取景器叠加辅助线（三分线、目标区、水平仪、方向箭头），引导用户移动到构图更好的位置再按快门。产品形态为「相机 + 轻社区」MVP：启动页 → 本地登录/注册 → 三 Tab 主页（相机/社区/个人）+ 设置 + 相册 + 编辑资料。

**AI 链路真实口径**（docs 09/10）：v9 交付物是 embedding 模型（`student_model.static_int8.onnx`，301KB，输入 `[1,3,224,224]` RGB NCHW，输出 512 维 L2 归一化向量）+ 728 条模板索引。App 负责：抽帧 → ONNX 推理 → 余弦检索 top8 → 规则重排 top5 → 模板 metadata 转辅助线。**14 种 GuidanceCue（移动/旋转指令）模型不直接输出**，需 App 侧几何检测（主体框、水平线）补充。

## 三、技术栈适配性结论

**选型方向没有问题，问题在工程纪律。**

- Compose + CameraX + Kotlin 2.0 是未来 3-5 年的主流正路，无需更换。
- ONNX Runtime 与 AI 侧交付物严格对齐（输入归一化、manifest、runtime 版本均一致），做对了。
- **TFLite + tflite-gpu 依赖已失去意义**（v9 确定走 ONNX），白占包体，应删。
- **Hilt 形同虚设**：`AppModule` 写了 V9 自动装配，但三个 ViewModel 全部绕过 DI 自己 new（`PipelineViewModel.kt:29-37`、`CameraViewModel.kt:63-64`），`@Singleton` 的 V9 装配永远不会被触发。
- **三套重复代码**：`modules/`（参考实现）、`teammate-repo/`（整个 app 的旧副本）、`aicamera-app/`（活代码）并存，无单一事实源，迭代漂移风险高。
- **零测试**：`CoordinateMapper`、`GuideLineParser`、状态机等纯逻辑全部裸奔——下文 P0 bug 有任何一个单测都能拦住。
- AGP 8.7.3 配 Gradle 9.3.0 超出官方测试矩阵（`.kotlin/errors` 有一次 daemon 崩溃日志，已自行恢复），建议锁 Gradle 8.9 或升 AGP；`kotlinOptions` DSL 已废弃。

**结论：栈不拖后腿，「接线」和工程卫生拖后腿。**

## 五、问题清单

### 🔴 P0 — AI 链路根本跑不通（三个叠加，任一都致命）

**P0-1. 模板索引加载必然崩溃** — `pipeline/V9TemplateIndex.kt:89`
```kotlin
val emb = temp.copyOfRange(i * dim, (i + 1 * dim).coerceAtMost(temp.size))
```
运算符优先级错误：`i + 1 * dim` = `i + dim`，应为 `(i + 1) * dim`。i=0 侥幸正确，i=1 切出 1 个元素被过滤，**i=2 时 `copyOfRange(1024, 514)` 起点大于终点直接抛 IllegalArgumentException** → `load()` 捕获后返回 false → 索引加载永远失败。

**P0-2. DI 被绕过，V9 装配是死代码** — `viewmodel/PipelineViewModel.kt:29-37`
ViewModel 不用 Hilt 注入，自己 `new FakeInferenceAdapter()`；`AppModule.provideInference()`（V9 自动检测）无任何调用方；`setRealInference()`（:76）也无人调用。就算修好 P0-1，V9 依然不会被用到。

**P0-3. 首启竞态：模型复制 vs 推理器装配** — `AiCameraApp.kt:24` 在 IO 线程异步复制 5MB 资产，而 `provideInference` 在 ViewModel 创建时同步检查文件存在性。首次启动若复制未完成，Fake 推理器作为单例锁死一整局；更糟的是复制中途被读到（embeddings.f32 写了一半），会加载出条目不齐、行错位的索引，静默默认错模板。

### 🟠 P1 — 严重功能错误

**P1-4. 模板稳定切换逻辑死锁** — `pipeline/V9Inference.kt:92-99`：新模板连续领先时 `stableCount` 每次都因 `top1 != previousTemplateId` 被重置为 1，永远到不了 `stableSwitchFrames=2`，且提前 return 阻止 `previousTemplateId` 更新。**第一个模板选定后永不切换。**

**P1-5. 预处理从不旋转图像** — `pipeline/FramePreprocessor.kt:59-90`：`rotateBitmap()` 写好了却没人调用，v9 协议明确要求「先按 rotationDegrees 转正」。竖屏拍摄时模型吃到横躺 90° 的图，embedding 检索质量受损；前摄镜像也未按协议处理。另外 `targetSize=320` 与模型 224 不一致，二次缩放纯浪费。

**P1-6. 参数解析把水平仪角度钳死** — `overlay/model/GuideLineModels.kt:178`：私有 `float()` 把所有参数 `coerceIn(0f, 1f)`，`angle_degrees`（正常范围 ±几度）负值归 0、>1 归 1，**水平仪永远显示绿色水平**。V9 输出的 `reference_y` 在 `HorizonParams` 里连字段都没有，静默丢弃。

**P1-7. 坐标旋转映射几何错误** — `overlay/CoordinateMapper.kt:118-133`：90°/270° 分支把点映射到转置坐标系（x 上限变成 viewHeight），竖屏下 rotationDegrees=90 时目标区被画到屏幕外；而 `GuideLineRenderer.kt:132` 画主体框调用 `mapRect` 又没传 rotationDegrees——两条路径一个画屏外、一个画错位置。

**P1-8. 照片不进系统相册** — `camera/CameraCapture.kt:135-149`：注释写「保存到系统相册」，实际存到 `getExternalFilesDir`（应用私有目录）且未做 MediaStore 插入/扫描 → 系统相册看不到照片、卸载即丢；`getLatestPhotoUri()` 查 MediaStore 自然永远查不到 → **左下角缩略图功能恒为空**。Android ≤9 路径写公共目录还没查运行时权限。

**P1-9. 辅助线数据流断在新旧渲染层之间** — `ui/screen/CameraScreen.kt:120-129`：旧 `CompositionOverlayView` 的 `update()` 不再被调用（LaunchedEffect 是空壳），V9/Fake 生成的 7 类辅助线**全部不渲染**；新 `ComposeGuidanceOverlay` 只画静态三分线+固定目标框。**AI 管线的全部产出只改变了左上角 HUD 的一行调试文字。**

### 🟡 P2 — 隐患与漏洞

**并发/生命周期**
- `FrameScheduler.kt:67`：CAS 占锁成功后若 executor 已 shutdown，`execute()` 抛 RejectedExecutionException → 门闩永久卡死 + ImageProxy 泄漏。
- `FrameScheduler.kt:39-41,162`：耗时统计 ArrayDeque 推理线程写、主线程读，无同步。
- `FramePipeline.kt:73`：推理抛异常时 originalBitmap 回收被跳过（缺 try/finally），Bitmap 泄漏。
- `CameraGestureDispatcher.attach`（`CameraScreen.kt:213`）捕获初始化时的 Camera 实例，切换前后摄后捏合变焦/点击对焦操作的是已失效的旧 Camera。
- `AppModule.provideInference` 在主线程同步做 ONNX session 创建 + 3.3MB 索引加载 + 728 行 JSON 解析 → 首次进相机页卡顿。
- 旧 `CompositionOverlayView` 只剩对焦圈功能，但两个无限动画仍常驻驱动 invalidate（`AnimationController.kt:20-43`），空 View 也在 60fps 空转耗电。

**安全（MVP 可接受，上线前必须清账）**
- `AuthRepository.kt:205`：SHA-256 单轮哈希存密码（应 PBKDF2/bcrypt/argon2）；`:212` session token 用非加密随机数；`:240` 固定验证码 `123456`；`:87` 日志明文打印手机号（PII 泄漏）；SharedPreferences 未加密 + `AndroidManifest.xml:37` `allowBackup="true"` → 凭证可随备份导出。
- `proguard-rules.pro` 缺 ONNX Runtime 的 keep 规则，release 混淆后 JNI 层有崩溃风险。
- 注册第二个账号会静默覆盖第一个账号的数据（`AuthRepository.kt:74` 只挡同手机号）。

**包体/资源**
- assets 打包了 Android 用不上的 fp32 对照模型（877KB）、Python 版 usearch 索引（~1.5MB）、质量报告（333KB）→ APK 白大 ~2.7MB；复制时不校验 sha256（manifest 里明明给了 hash）。
- `build.gradle.kts:77-78` TFLite 两套依赖可整体删除。

### ⚪ P3 — 代码质量

- `pipeline/CompositionStateMachine.kt` 死代码（与 GuidanceStateMachine 重复）；`camera/CameraPermission.kt`（Fragment 版）无人使用；`ProModePanel`/`CameraProControls` 写完未接入任何界面。
- `FramePreprocessor.targetSize=320`（给 Fake 用）与 V9 需要的 224 语义混在一个 buffer 里。
- `PipelineResult.modelOutput: Any?` 类型擦除，下游靠 `as? FakeInferenceOutput` 猜。
- `currentRenderInput`（`CameraScreen.kt:84`）收集了却不用，每次推理结果白触发一次全屏重组。
- `CameraControls.enablePinchToZoom` 与 `CameraFocus.enableTapToFocus` 都调用 `setOnTouchListener`，互相覆盖（代码注释自认）；统一手势分发器已存在，旧 API 应退役。
