## 一、P0 — AI 链路跑通（3/3 已修）

### P0-1 模板索引加载崩溃 ✅
- **文件**：`pipeline/V9TemplateIndex.kt`
- **改动**：`(i + 1 * dim)` → 纯函数 `sliceEmbedding(flat, row, dim)`（`row * dim` 起、步长 dim），带边界 `require` 校验；
- **加固**：metadata 解析失败的行会同步丢弃对应 embedding，防止行错位「静默默认错模板」；embedding 与 metadata 数量不一致时截断对齐并告警；
- **回归防护**：新增 `app/src/test/.../V9TemplateIndexSliceTest.kt`（7 个用例，含「728 行全量切片不抛异常」）。

### P0-2 DI 绕过、V9 装配是死代码 ✅
- **改动**：三个 ViewModel 全部改为 `@HiltViewModel` 构造注入——
  - `PipelineViewModel`：注入 `FramePipeline` + `AiEngineManager`，订阅引擎状态，READY 后 `pipeline.setInference(v9)` 热替换（Fake → V9-ONNX，无需重启）；
  - `CameraViewModel`：注入 `CameraManager` + `CameraCapture`（不再是 AndroidViewModel）；
  - `RenderViewModel`：`@Inject constructor()`；
- `AppModule` 删掉主线程做 I/O 的 `provideInference`；管线默认 Fake 兜底。

### P0-3 首启竞态 ✅
- **新增** `pipeline/AiEngineManager.kt`（`@Singleton`）：统一负责 复制资产 → sha256 校验 → 加载 ONNX → 加载索引，全程 IO 线程，状态经 `StateFlow<State>` 广播（IDLE/COPYING/LOADING/READY/FAILED）；
- `AiCameraApp.onCreate` 只做一件事：`aiEngine.start()`（幂等，FAILED 可重试）；
- 任何一步失败 → FAILED，管线保持 FakeInference 兜底，App 不崩；
- **附带修复**：ONNX session 创建 + 3.3MB 索引加载不再发生在主线程。

## 二、P1 — 严重功能错误（6/6 已修）

### P1-4 模板切换死锁 ✅
- **文件**：`pipeline/V9Inference.kt` → `selectStable()`
- **改动**：「挑战者候选」独立计数——现任 top1 则清空候选；margin < 0.01 不换；新候选连续 2 帧领先才换王。旧实现里计数器每帧重置为 1，模板永远不换。

### P1-5 预处理不旋转/不镜像/尺寸错 ✅
- **文件**：`pipeline/FramePreprocessor.kt`
- **改动**：处理链对齐 v9 协议——`toBitmap → rotateBitmap(rotation) → (前摄)mirrorBitmap → resize 224×224 → float buffer`；`targetSize` 默认 320 改为 **224**（AppModule 同步）；`PreprocessedFrame.rotation` 恒为 0（下游无需再旋转）。

### P1-6 参数解析钳死角度、丢弃 reference_y ✅
- **文件**：`overlay/model/GuideLineModels.kt`、`overlay/GuideLineRenderer.kt`、`pipeline/V9Inference.kt`
- **改动**：新增不 clamp 的 `floatUnclamped()` 供 `angle_degrees` 使用（坐标类参数仍 clamp）；`HorizonParams` 增加 `referenceY` 字段并在渲染层画水平参考虚线；V9 的水平仪与参考线合并为一条 `horizon_level`。

### P1-7 坐标旋转映射几何错误 ✅
- **文件**：`overlay/CoordinateMapper.kt`
- **改动**：旋转改在**归一化空间**完成（90°: `(x,y)→(1-y,x)`，含推导注释），再乘 View 尺寸——消除旧实现 90°/270° 映射到转置坐标系、目标区画出屏幕外的问题；
- `GuideLineRenderer.drawSubjectBox` 补上漏传的 `rotationDegrees`，与 `drawTargetZone` 行为一致；
- 配合 P1-5：帧已预处理转正，渲染层实际收到 rotationDegrees=0，双保险。

### P1-8 照片不进系统相册 ✅
- **文件**：`camera/CameraCapture.kt`
- **改动**：Android 10+ 经 `MediaStore.Images` + `RELATIVE_PATH=Pictures/AiCamera` 正确插入（系统相册可见、`getLatestPhotoUri`/相册页立即可用）；Android 9- 先查 WRITE 运行时权限、写公共目录后 `MediaScannerConnection` 扫描；新增 `saveToGallery` 参数（false → 应用私有目录，对应设置页「保存到系统相册」开关）。

### P1-9 辅助线数据流断裂 ✅
- **文件**：`ui/screen/CameraScreen.kt`
- **改动**：`renderViewModel.renderInput.collect` 真正调用 `overlayView.update(input.filteredBy(settings), animate = true)`——AI 产出的目标区/主体框/水平仪/箭头重新可见；
- 职责分层：旧 `CompositionOverlayView` = AI 动态辅助线 + 对焦圈；`ComposeGuidanceOverlay` = 静态三分线/目标框 + 方向指令动画；
- 删除空转的 `currentRenderInput` 死状态；HUD 增加「引擎/AI 状态」两行（可肉眼确认 V9 是否上线）；`GuidanceMessage` 的 `[Demo]` 标注去掉。

## 三、P2 — 隐患与漏洞（已修）

**并发/生命周期**
- `FrameScheduler`：`execute()` 包 try/catch `RejectedExecutionException`——release 竞态时门闩复位 + 帧关闭，不再永久卡死；耗时统计 `ArrayDeque` 全部经 `statsLock` 同步读写；管线主体抽成 `runPipeline()`；
- `FramePipeline`：Bitmap 回收改 try/finally，推理抛异常不再泄漏；
- 手势重挂：`CameraViewModel` 新增 `cameraBindVersion`（init/切换/重绑成功即自增），CameraScreen 监听该值 `detach + attach` 到新 Camera 实例——切前后摄后捏合变焦/点击对焦不再失效；
- `CompositionOverlayView`：动画按内容启停（无可见辅助线时 `animController.stop()`），空 View 不再 60fps 空转耗电；对焦圈动画不受影响；
- `V9EmbeddingRuntime`：`SessionOptions` 用后关闭（AutoCloseable 泄漏）。

**安全**
- `AuthRepository`：密码哈希 SHA-256 单轮 → **PBKDF2-HmacSHA256 / 20,000 迭代**（⚠️ 旧哈希失效，本地老账号需重新注册）；session token → **SecureRandom 24 字节**；日志移除手机号/用户名 PII；固定验证码 `123456` 保留（MVP 联调用，已加醒目警告，接后端前必须移除）；
- `AndroidManifest`：`allowBackup="false"`（凭证不随备份导出）；
- `proguard-rules.pro`：补 **ONNX Runtime keep 规则**（JNI 按名查找，release 混淆必需）。
