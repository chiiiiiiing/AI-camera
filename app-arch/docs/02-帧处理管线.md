# 模块二：实时帧处理管线

> 管线是相机和 AI 之间的桥梁。**不依赖队友，建议第 1–2 周完成。** 没有模型也能跑——用假逻辑（如统计帧平均亮度）替换推理环节即可验证整条管线。

---

## 2.1 管线流程

```
ImageAnalysis 回调 (YUV_420_888, 30 FPS)
        │
        ▼
  [帧调度器]  跳帧策略：推理中则跳过，只取最新
        │
        ▼
  [预处理器]  YUV→RGB Bitmap | resize 到模型输入尺寸 | normalize
        │
        ▼
  [推理器]    喂入 LiteRT/MediaPipe | 后台线程
        │
        ▼
  [结果解析器] 提取辅助线参数 | 坐标映射 | 时序平滑
        │
        ▼
  [渲染回调]   post 到主线程 → 更新 Overlay
```

## 2.2 帧调度器（**最关键的部分**）

```kotlin
class FrameScheduler(
    private val inferenceExecutor: ExecutorService = Executors.newSingleThreadExecutor(),
    private val mainHandler: Handler = Handler(Looper.getMainLooper())
) : ImageAnalysis.Analyzer {

    @Volatile
    private var isProcessing = false

    // 性能统计
    private var frameCount = 0
    private var droppedCount = 0
    private var processedCount = 0

    override fun analyze(imageProxy: ImageProxy) {
        frameCount++

        if (isProcessing) {
            droppedCount++
            imageProxy.close()  // ★ 丢弃，不排队
            return
        }
        isProcessing = true
        processedCount++

        // 取出当前帧数据（在 imageProxy.close() 前完成）
        val bitmap = imageProxy.toBitmap()  // 或者直接传 YUV buffer
        val rotation = imageProxy.imageInfo.rotationDegrees

        inferenceExecutor.execute {
            try {
                val startTime = SystemClock.elapsedRealtime()
                val result = runInference(bitmap, rotation)
                val latency = SystemClock.elapsedRealtime() - startTime

                // 结果 + 耗时回调到主线程
                mainHandler.post {
                    onResult(result, latency)
                }
            } finally {
                isProcessing = false
                // ★ imageProxy 用完必须 close，否则 CameraX 不再吐帧
                if (!imageProxy.isClosed) {
                    imageProxy.close()
                }
            }
        }
    }

    fun getStats(): FrameStats = FrameStats(
        totalFrames = frameCount,
        processedFrames = processedCount,
        droppedFrames = droppedCount
    )
}
```

### 跳帧策略总结

```
预览帧率: 30 FPS（固定，CameraX 保证流畅预览）
推理帧率: 5–15 FPS（由 isProcessing 标记自然实现）

规则:
- isProcessing == true → 新帧 imageProxy.close()，丢弃
- isProcessing == false → 开始推理，置 true
- 推理完成 → 置 false，下一帧可进入
- 不使用队列！不使用队列！不使用队列！
```

## 2.3 ImageProxy → 模型输入

```kotlin
/**
 * 将 ImageProxy 帧预处理为模型输入的 ByteBuffer。
 * 当前使用 toBitmap() 做格式转换。后续可优化为直接操作 YUV Plane 数据，减少一次转换。
 */
fun ImageProxy.preprocess(targetSize: Int): ByteBuffer {
    // 1. YUV → RGB Bitmap
    val bitmap = this.toBitmap()

    // 2. Resize 到模型输入尺寸（如 320×320）
    val resized = Bitmap.createScaledBitmap(bitmap, targetSize, targetSize, true)

    // 3. 像素 → Float Tensor [1, targetSize, targetSize, 3]
    val byteBuffer = ByteBuffer.allocateDirect(4 * targetSize * targetSize * 3)
    byteBuffer.order(ByteOrder.nativeOrder())

    for (y in 0 until targetSize) {
        for (x in 0 until targetSize) {
            val pixel = resized.getPixel(x, y)
            byteBuffer.putFloat(Color.red(pixel) / 255.0f)
            byteBuffer.putFloat(Color.green(pixel) / 255.0f)
            byteBuffer.putFloat(Color.blue(pixel) / 255.0f)
        }
    }

    // 4. recycle 中间 Bitmap（toBitmap 返回的是新对象）
    if (resized != bitmap) resized.recycle()
    bitmap.recycle()

    return byteBuffer
}
```

> **性能优化方向**：`toBitmap()` 内部有一次 YUV→RGB 转换，后续可以绕过它直接用 YUV Plane 数据填充 ByteBuffer，省掉中间 Bitmap 分配。MVP 阶段先用 `toBitmap()` 跑通再说。

## 2.4 帧处理关键点总结

| 问题 | 方案 |
|------|------|
| 跳帧 | `STRATEGY_KEEP_ONLY_LATEST` + 手动 `isProcessing` 标记 |
| 格式转换 | YUV_420_888 → RGB Bitmap → Float ByteBuffer |
| 旋转处理 | 读取 `rotationDegrees`，传入模型或预处理时旋转 |
| 镜像处理 | 前置摄像头时 X 坐标翻转 |
| 线程模型 | 推理在 `SingleThreadExecutor`，渲染在主线程 |
| 内存管理 | 用完 `imageProxy.close()`，中间 Bitmap 及时 recycle |
| Buffer 复用 | `ByteBuffer.allocateDirect` 后可复用（`clear()` 后重新填入数据） |

## 2.5 不依赖队友的验证方式

在模型没到位时，用假推理逻辑验证管线：

```kotlin
// 假推理：计算帧平均亮度，验证管线是否正确
fun fakeInference(bitmap: Bitmap): FakeResult {
    var totalLuminance = 0L
    val sampleStep = 10  // 每 10 个像素采样一次

    for (y in 0 until bitmap.height step sampleStep) {
        for (x in 0 until bitmap.width step sampleStep) {
            val pixel = bitmap.getPixel(x, y)
            val r = Color.red(pixel)
            val g = Color.green(pixel)
            val b = Color.blue(pixel)
            // 感知亮度公式
            totalLuminance += (0.299 * r + 0.587 * g + 0.114 * b).toLong()
        }
    }

    val sampleCount = (bitmap.height / sampleStep) * (bitmap.width / sampleStep)
    val avgLuminance = totalLuminance / sampleCount

    return FakeResult(
        avgLuminance = avgLuminance,
        processingTimeMs = 0 // 实际推理时替换为真实耗时
    )
}
```

## 2.6 验证标准

- [ ] Logcat 中看到稳定 30 FPS 帧到达 CameraX 回调
- [ ] 5–15 FPS 被选中处理，其余帧跳过（看 droppedCount 日志）
- [ ] 单帧处理时间可测量（假推理应 < 5ms）
- [ ] ByteBuffer 复用无内存泄漏（观察 Profiler）
- [ ] imageProxy.close() 每次必定调用（加日志验证）
- [ ] 前后摄切换后管线继续正常工作
- [ ] 连续运行 10 分钟无 OOM、无 FD 泄漏
