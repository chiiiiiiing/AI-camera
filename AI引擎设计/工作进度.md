## 2026-07-09

### 进行中：阶段 2 — pilot-v2 筛选链路验证

**当前进度**：MediaPipe Pose 真实人体筛选已跑通；工具链已新增 SHA-256 完整性硬门槛。当前本地候选批次仍不能入库，原因是 29 条 accepted 记录的文件哈希与 manifest 不一致，必须修复或重采后才能继续正式预处理。

**已完成事项**：

1. **环境与测试验证**
   - 原 `tools/.venv` 的 `pip` 内部状态损坏，临时使用 `/tmp/ai-camera-check-venv` 完成验证
   - 安装并验证 `Pillow`、`jsonschema`、`mediapipe`
   - `tools/build_template_db` 单元测试从 23 项扩展到 26 项，全部通过
   - `collect_openverse.py --dry-run` 配置检查通过：14 类场景，目标 5,200 张
   - `validate_manifest.py` 结构校验通过：223 条记录

2. **MediaPipe 真实筛选跑通**
   - 在 macOS 沙盒内运行 MediaPipe 会因图形/缓存服务不可用崩溃，脱离沙盒并设置临时缓存目录后可正常运行
   - 旧逻辑下：175 条非 rejected 候选全部通过，其中人像 11/11 检出姿态
   - 新增哈希硬门槛后：175 条非 rejected 候选中 146 条通过，29 条因 `sha256_mismatch` 拒绝
   - 通过样本分布：人像 9、风景 106、静物 31；9 张人像均检测到 1 个 pose

3. **数据完整性问题确认**
   - `audit_dataset.py` 发现 35 条记录文件哈希不一致
   - 其中 29 条为 `accepted`，6 条为 `rejected`
   - 按类型分布：静物 15、人像 8、风景 12
   - 因哈希不一致，当前 raw 本地批次只能作为筛选链路验证样本，不能作为正式模板来源

4. **工具链防护加固**
   - `screen_candidates.py` 新增文件存在性与 SHA-256 校验；哈希不一致直接输出 `sha256_mismatch`，不再进入姿态检测
   - `preprocess.py` 新增 SHA-256 校验；哈希不一致时停止生成 CV job
   - 新增单元测试覆盖哈希不一致拒绝逻辑
   - 当前 `preprocess.py tools/raw_photos/manifest.jsonl` 会按预期在第 23 行哈希不一致处停止

**下一步**：

1. 修复或废弃当前 29 条 accepted 但哈希不一致的记录；更推荐直接重采 pilot-v2-clean
2. 重采时保持：CC0/PDM、4:3/3:4、媒介负面词过滤、真实人体检测、人工版权/肖像权复核
3. 重采后必须同时通过 `validate_manifest.py`、`audit_dataset.py`、`screen_candidates.py`
4. 三项检查全绿后再运行 `preprocess.py` 生成正式 CV jobs
5. 代码和文档更新需要在 Windows 存储电脑上执行 Git 提交/推送，避免 SMB 上 Git index 写入问题

## 2026-07-08

### 进行中：阶段 2 — 模板库构建

**当前进度**：首批候选已暴露系统性质量问题并全部隔离；采集准入规则已重构，等待真实人体检测跑通后重新采集 pilot-v2。

**已完成事项**：

1. **数据来源合规修正**
   - 核对现行官方条款后，不再默认使用 Unsplash/Pexels 普通 API 批量构建 AI 模板库
   - Unsplash 的 AI/ML 用途需走其数据授权渠道；Pexels 的 ML 提取和批量复制需取得明确许可
   - 初期改用 Openverse 检索的 CC0/PDM 候选照片，并保留来源、作者、许可证及落地页
   - 所有照片仍须人工复核；人像额外检查肖像权

2. **照片收集工具链** (`tools/build_template_db/`)
   - 建立 14 类场景配置，目标模板总数 5,200 张
   - 完成 Openverse 采集器：许可证过滤、分辨率过滤、SHA-256 去重、断点续跑、错误清单
   - 建立原始照片 JSON Schema 和无依赖核心校验器
   - 建立来源策略：Unsplash/Pexels 在取得书面许可前保持禁用

3. **真实 API 烟雾测试**
   - 已形成 37 条候选记录：36 张现存图片 + 1 条人工淘汰记录
   - 现存样本覆盖：人像 16、风景 7、静物 13
   - `manifest.jsonl` 通过文件、哈希、重复项、尺寸和授权字段审计
   - 自动化测试：18/18 通过
   - 发现并处理 Openverse 原始尺寸与实际可下载尺寸不一致、全尺寸代理失败等问题

4. **人工审核与预处理骨架**
   - `review_candidates.py`：接受/淘汰记录、原因和时间戳，避免被淘汰照片再次下载
   - `audit_dataset.py`：审计文件、SHA-256、重复项、尺寸、许可证和最终审核状态
   - `preprocess.py`：生成 36 条 CV 任务，已固定主人物选择、COCO 17 点归一化、关节角和 256 维向量校验接口
   - 用户删除的草地风景样本已标记为 `rejected`，不会进入预处理任务

5. **pilot-v1 质量事故与修正**
   - 用户发现人像目录混入火车、动物、花和街景，确认旧逻辑错误地把图库搜索结果当成视觉识别结果
   - 36 张现存图中仅 10 张接近手机 4:3/3:4，旧批次全部隔离，正式预处理任务数归零
   - 新增 4:3/3:4 硬过滤和 painting/illustration/drawing/artwork 等媒介负面词过滤
   - 新增 `screen_candidates.py`：人像必须通过真实 Pose Landmarker 检测，非人像检测到显著人物时拒绝
   - 中国人像改为中国场景/中文与 East Asian 元数据召回后人工确认，不做肤色或种族自动分类
   - 不直接抓取中国社交媒体；只导入自有或作者书面授权内容
   - 发现 Ultralytics YOLOv8 Pose 对闭源商业 App 存在 AGPL/企业许可要求，MVP 优先验证 Apache-2.0 的 MediaPipe Pose

**下一步**：

1. 恢复运行额度后执行 MediaPipe 真实人体筛选
2. 按新硬门槛重新采集 pilot-v2，不复用旧批次作为模板
3. 对中国人像建立自有拍摄/创作者书面授权导入渠道
4. 评测 MediaPipe Pose 后再决定是否购买 Ultralytics Enterprise 或彻底替换 YOLOv8-Pose

## 2026-07-07

### 已完成：阶段 1 — 环境搭建与脚手架

**耗时**: 1 天（实际约 3 小时）

**完成事项**:

1. **项目目录结构创建**
   - `engine/` — C++ AI 引擎源码目录（含 core / inference / preprocess / utils / jni / tests / bench / models）
   - `tools/` — Python 工具链目录（含 build_template_db / quantize）
   - `.github/workflows/` — CI 配置

2. **CMake 构建系统配置**
   - `engine/CMakeLists.txt` — C++17, 支持 macOS 本地编译和 Android NDK 交叉编译
   - 三方依赖通过 Homebrew 管理: Eigen 5.0.1, nlohmann-json 3.12.0, Catch2 3.15.1
   - USearch 留待阶段 4 集成（单头文件方式）

3. **引擎公开接口定义**
   - `engine/include/engine.h` — 完整 C 接口（~150 行）
   - 定义了所有输入/输出数据结构：
     - `CameraTarget` — 相机目标点（替代旋转箭头）
     - `PoseArrow` — 姿势引导箭头（仅人像）
     - `PoseOverlay` — 虚线人形（17 个 COCO 关键点）
     - `CompGuides` — 构图辅助线（九宫格、地平线、主体区域、引导线）
     - `TextSuggestion` — LLM 文字建议
   - `GuidanceOutput` 包含 `photo_type` 字段支持人像/风景/静物三类
   - 生命周期 API: init / shutdown / is_ready / process_frame / trigger_rescan / get_status

4. **引擎骨架实现**
   - `engine/src/core/engine.cpp` — 所有函数返回合理的零值/默认值
   - `engine_get_version()` 返回 `"0.1.0-dev"`

5. **单元测试**
   - `engine/tests/test_engine_basic.cpp` — 5 个测试用例，23 个断言
   - 覆盖: 版本号、初始化/销毁、帧处理、null sensor 鲁棒性、多轮 init/shutdown 泄漏检测

6. **CI 配置**
   - `.github/workflows/engine-ci.yml` — 自动编译 + 运行测试

7. **编译验证**
   ```
   macOS: cmake -B build && cmake --build build  ✅
   测试:   ./build/engine_tests                    ✅ 5/5 passed
   ```

**当前产物**:
```
engine/build/libai_photo_engine.dylib   ← macOS 等价于 Android .so
engine/build/engine_tests               ← 单元测试可执行文件
```

**下一步**: 阶段 2 — 模板库构建（照片收集 + CV 预处理 + LLM 标注 + USearch 索引）
