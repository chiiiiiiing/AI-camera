## 2026-07-07

### 已完成：阶段 1 — 环境搭建与脚手架

**耗时**: 1 天（实际约 3 小时）

**完成事项**:

1. **项目目录结构创建**
   - `engine/` — C++ AI 引擎源码目录（含 core / inference / preprocess / utils / jni / tests / bench / models）
   - `tools/` — Python 工具链目录（含 build_template_db / quantize）
   - `.github/workflows/` — CI 配置

2. **CMake 构建系统配置**
   - `engine/CMakeLists.txt` — C++17, 支持 macOS 本地编译和 Android NDK 交叉编译
   - 三方依赖通过 Homebrew 管理: Eigen 5.0.1, nlohmann-json 3.12.0, Catch2 3.15.1
   - USearch 留待阶段 4 集成（单头文件方式）

3. **引擎公开接口定义**
   - `engine/include/engine.h` — 完整 C 接口（~150 行）
   - 定义了所有输入/输出数据结构：
     - `CameraTarget` — 相机目标点（替代旋转箭头）
     - `PoseArrow` — 姿势引导箭头（仅人像）
     - `PoseOverlay` — 虚线人形（17 个 COCO 关键点）
     - `CompGuides` — 构图辅助线（九宫格、地平线、主体区域、引导线）
     - `TextSuggestion` — LLM 文字建议
   - `GuidanceOutput` 包含 `photo_type` 字段支持人像/风景/静物三类
   - 生命周期 API: init / shutdown / is_ready / process_frame / trigger_rescan / get_status

4. **引擎骨架实现**
   - `engine/src/core/engine.cpp` — 所有函数返回合理的零值/默认值
   - `engine_get_version()` 返回 `"0.1.0-dev"`

5. **单元测试**
   - `engine/tests/test_engine_basic.cpp` — 5 个测试用例，23 个断言
   - 覆盖: 版本号、初始化/销毁、帧处理、null sensor 鲁棒性、多轮 init/shutdown 泄漏检测

6. **CI 配置**
   - `.github/workflows/engine-ci.yml` — 自动编译 + 运行测试

7. **编译验证**
   ```
   macOS: cmake -B build && cmake --build build  ✅
   测试:   ./build/engine_tests                    ✅ 5/5 passed
   ```

**当前产物**:
```
engine/build/libai_photo_engine.dylib   ← macOS 等价于 Android .so
engine/build/engine_tests               ← 单元测试可执行文件
```

**下一步**: 阶段 2 — 模板库构建（照片收集 + CV 预处理 + LLM 标注 + USearch 索引）
