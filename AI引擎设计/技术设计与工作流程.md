# 技术设计与工作流程

## 当前目标

阶段 2 的核心是建立摄影模板库，并让端侧引擎能加载模板索引做推荐。当前重点不是做完整 App UI，而是把数据链路、索引产物和 C++ 加载能力稳定下来。

## 目录职责

| 目录 | 用途 |
|---|---|
| `tools/build_template_db/` | 模板库采集、导入、筛选、标注、metadata、embedding、索引工具 |
| `tools/raw_photos/` | 原始候选和人工审核 manifest |
| `tools/preprocessed/` | CV 预处理、embedding、annotation、template index 产物 |
| `engine/` | C++ 端侧引擎和 host tests |
| `AI引擎设计/` | 当前决策、状态和待办 |

## 数据链路

```text
图片来源
  -> raw manifest
  -> SHA / 尺寸 / 比例 / 关键词 / 重复校验
  -> 人像姿态筛选
  -> 人工质量审核
  -> CV preprocessing jobs
  -> 视觉标注 requests / batches / results
  -> annotations.jsonl
  -> template_metadata.jsonl
  -> teacher embedding / distilled embedding
  -> portable template index
  -> USearch index
  -> C++ engine load / query
```

## 当前正式库

- 正式非人像模板：104 条。
- embedding：MobileCLIP2-S0 原型生成，256 维 pairwise 投影，全部 ready；商业路线已改为自有端侧模型蒸馏。
- 索引：`tools/preprocessed/template_index.visual-clean/`。
- C++：已支持 exact fallback 加载 portable index。

## 新批次规则

新素材必须先进入独立批次，例如：

- `tools/raw_photos/new_batch/manifest.jsonl`
- `tools/raw_photos/new_batch/manifest.cv-preprocess-clean.jsonl`
- `tools/raw_photos/new_batch/review_pack/`

本批次素材授权已由用户于 2026-07-18 确认。新批次已完成人工审核、视觉标注、teacher embedding、teacher index、蒸馏数据集、多版 student 训练、v9 ONNX 导出和 static int8 ONNX 量化；当前 Android 首发 runtime 候选是 `tiny_cnn_v9_wide_topk_siglip2_512` 的 static int8 ONNX 包。新批次在真机性能与产品灰度达标前，不合并到正式 `visual-clean`。

## 端侧运行架构

短期实现：

- `engine_init` 从 `model_dir/template_index.visual-clean/` 加载索引。
- 索引缺失时引擎降级启动，不崩溃。
- `engine_get_status_json` 暴露索引 ready/count/dimension/status/warning。
- 当前 C++ 使用 exact fallback，不依赖坏掉的 `engine/src/utils/usearch.hpp`。

后续生产实现：

- 替换真实 USearch C++ 依赖。
- Android assets 首次复制到 app-private 目录。
- native engine 从普通文件路径加载 `.idx` 和 metadata。
- Android App 侧用 ONNX Runtime Mobile 跑 v9 static int8 embedding，并按 500ms-1000ms 抽帧或画面变化触发。
- `engine_process_frame` 后续接真实帧 embedding 后，再触发模板检索和重排。

## 下一步工程顺序

1. 交付 `App技术设计/09-AI接入包说明.md` 给 Android 队友。
2. App 侧接入 v9 static int8 ONNX：frame -> embedding -> topK 模板召回 -> top5 规则重排。
3. 做 Android app-private 目录加载验证，模型和索引必须同版本复制。
4. 在目标 Android 设备实测 p50/p90、内存、发热和连续预览稳定性。
5. 接真实 USearch C++ backend，或在 App 侧先用 exact fallback 验证功能。
6. 继续用 `evaluate_template_index_quality.py` 对 teacher、FP32 student、static int8 ONNX student 做持续 A/B 质量评估。
7. 达到质量和端侧性能阈值后，再决定是否把 new_batch 合并为正式索引。

## 不要做

- 不重复下载已有模型。
- 不重复生成已有 104 条正式 embedding。
- 不把根目录 `results/` 当正式输入。
- 不把 pending 新素材直接推进正式索引。
- 不伪造 embedding 或视觉标注。
