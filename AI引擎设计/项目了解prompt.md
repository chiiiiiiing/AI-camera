# 项目背景与核心目标
产品目标是开发一款纯端侧运行的智能相机，提供零延迟的构图、姿势和机位指导。
核心技术限制：算法必须在手机本地运行，单帧推理控制在 20ms 以内（保证 30fps 帧率），模型总体积须控制在 20MB 以内。

# 系统核心架构设计（分层协同异步架构）
整个系统底层依赖双圈层异步架构，请在后续代码编写中严格保持管线的解耦：
1. **外圈：高频语义检索（低频触发，如场景切换时）**
   - **技术栈**：端侧量化多模态模型（如 Mobile-CLIP）结合本地轻量向量数据库（USearch）。
   - **执行逻辑**：计算当前画面的 Embedding，在本地检索“满分摄影模板库”，瞬间锁定最佳参考模板，并抽离其对应的结构化目标特征锚点（Target Vector）。
2. **内圈：底层物理对齐（高频实时，30fps）**
   - **技术栈**：极轻量关键点模型（如 YOLOv8-pose Nano）与手机原生惯性传感器（IMU）。
   - **执行逻辑**：提取实时相机的骨骼点与手机俯仰角，与目标特征锚点进行纯数学的差值运算（$\Delta$），实时驱动前端 UI 的位移和对齐引导。

# 核心工程痛点与既定解决方案
在设计具体算法模块时，必须实现以下三大规避方案：
1. **视觉无关特征剥离（解决向量检索被服装色彩干扰）**：
   在提取 CLIP 向量前，必须接入轻量语义分割管线（如 MobileSAM）生成人体 Mask，将人物区域像素强制置黑。迫使检索算法仅对背景几何透视和空间氛围进行纯粹检索。
2. **肢体形变归一化（解决不同身材比例的容错失效）**：
   废弃绝对像素坐标比对逻辑。采用以“左肩至右髋”为基准单位长度的空间等比缩放（Root-centered Scaling），同时将位置匹配升维为**关节拓扑夹角（Joint Angles）**比对，并设定合理的容差阈值（如 ±10°）。
3. **引入语义翻译层（消除规则引擎的机械感）**：
   将底层算出的多维物理差值 $\Delta$（如“曝光偏暗”且“机位偏低”）打包为结构化 JSON/Prompt，交由常驻内存的端侧 1B 级大语言模型（如 Qwen-1.5-0.5B-Chat）进行语义融合，输出通俗、自然的口语化指导。
