# 模块三：AI 模型接入

> 模型是队友训练的。你的工作：**接进来、跑起来、稳定输出**。
>
> ⚠️ LiteRT 加载骨架不依赖队友（可用公开模型验证），实际模型接入依赖队友的 `.tflite` + 输入/输出规格。

---

## 3.1 模型做了什么（队友侧）

```
📷 相机画面
    │
    ▼
🧠 队友的模型:
    Step 1 — 场景识别：这是人像？风景？食物？建筑？街拍？
    Step 2 — 构图策略匹配：根据场景选策略（三分法/对称/引导线/框架构图...）
    Step 3 — 辅助线计算：输出该策略对应的辅助线坐标、类型、动画参数
    │
    ▼
📱 你的 App 收到: 辅助线参数列表 → 渲染到屏幕上
```

素材来源：B 站/抖音上有大量摄影构图教程（三分法、对称构图、引导线构图、留白、框架构图等等），队友会从中提炼构图策略并训练模型。

---

## 3.2 你的职责

1. **接收模型文件**：队友给你 `.tflite` 文件 + 输入/输出规格文档
2. **加载模型**：App 启动时异步加载，避免阻塞主线程
3. **预处理**：按队友指定的尺寸和归一化方式处理帧
4. **执行推理**：调用 LiteRT 推理 API
5. **解析输出**：把模型输出的 float 数组/Tensor 反序列化为辅助线参数
6. **结果平滑**：EMA 平滑避免辅助线抖动
7. **模型更新**：支持 OTA 下发新版模型

---

## 3.3 Android 推理方案选型

| 框架 | 适用场景 | 推荐度 |
|------|----------|--------|
| **LiteRT（原 TFLite）** | 队友提供 `.tflite` 模型 | ⭐⭐⭐ 首选 |
| **MediaPipe** | 需要预置的检测/分割/姿态能力 | ⭐⭐ |

> 首选 LiteRT：队友训模型 → 导出 `.tflite` → 你直接加载。最简单、最可控。

## 3.4 LiteRT 集成

### Gradle 依赖

```kotlin
dependencies {
    implementation("org.tensorflow:tensorflow-lite:2.16.1")

    implementation("org.tensorflow:tensorflow-lite-support:2.16.1")   // 预处理工具
}
```

### 模型加载（GPU 优先 → CPU fallback）

```kotlin
class CompositionModel(context: Context) {
    private var interpreter: Interpreter
    private var inputSize: Int  // 模型输入边长，如 320

    init {
        val modelBuffer = FileUtil.loadMappedFile(context, "composition_model.tflite")
        val options = Interpreter.Options().apply {
            // 优先 GPU，fallback CPU
            try {
                addDelegate(GpuDelegate())
                Log.i("Model", "Using GPU delegate")
            } catch (e: Exception) {
                Log.w("Model", "GPU delegate not available, using CPU with 4 threads")
                setNumThreads(4)
            }
        }
        interpreter = Interpreter(modelBuffer, options)
        inputSize = interpreter.getInputTensor(0).shape()[1]  // 从模型读取输入尺寸
    }

    fun predict(inputBuffer: ByteBuffer): ModelOutput {
        // 输出 buffer 大小跟队友对齐
        val outputShape = interpreter.getOutputTensor(0).shape()
        val outputSize = outputShape.fold(1) { acc, dim -> acc * dim }
        val outputBuffer = Array(1) { FloatArray(outputSize) }

        interpreter.run(inputBuffer, outputBuffer)
        return parseOutput(outputBuffer[0])
    }

    fun close() {
        interpreter.close()
    }
}
```

### 推理调用（接入帧管线）

```kotlin
// 在 FrameScheduler 的推理线程中调用
fun runInference(bitmap: Bitmap, rotation: Int): ModelOutput {
```

## 3.5 结果平滑（防抖）

```kotlin
class ResultSmoother(private val alpha: Float = 0.3f) {
    private var smoothed: ModelOutput? = null

    fun smooth(raw: ModelOutput): ModelOutput {
        if (smoothed == null) {
            smoothed = raw
            return raw
        }
        // EMA: new = alpha * raw + (1-alpha) * prev
        smoothed = smoothed!!.lerp(raw, alpha)
        return smoothed!!
    }
}
```

## 3.6 不依赖队友的验证方式

用 Google 公开的 MobileNet tflite 先把加载和推理循环跑通：

1. 下载 [MobileNet v1 tflite](https://tfhub.dev/google/lite-model/imagenet/mobilenet_v1_100_224/classification/5)
2. 放入 `assets/` 目录
3. 加载 → 输入 224×224 帧 → 推理 → 拿到分类结果
4. 验证 GPU Delegate 是否正常工作
5. 测量单次推理耗时

等队友给模型后：替换 `.tflite` 文件 → 改输入尺寸 → 改输出解析。管线的其余代码不动。

## 3.7 验证标准

- [ ] 模型文件能从 assets 加载无异常
- [ ] GPU Delegate 在支持的设备上生效（日志确认）
- [ ] 不支持的设备正确 fallback 到 CPU
- [ ] 单次推理耗时在目标范围内（< 100ms 中高端 / < 200ms 低端）
- [ ] 连续推理 10 分钟内存稳定
- [ ] EMA 平滑后辅助线无明显抖动
- [ ] 前后摄切换后推理继续正常
