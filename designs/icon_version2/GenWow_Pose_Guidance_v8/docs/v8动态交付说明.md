# GenWow 人物姿势引导 v8 · APP 动态交付补充包

## 与 v7 的关系
v8 **保留 v7 原始人物轮廓 SVG**，没有再次凭空重绘人物比例。新增了与 SVG 共坐标系的**人工关键点标定、调试可视化、纠错弧线组件样式、模拟帧序列及 Android 数据契约**。原 AI-camera 仓库没有修改。

## 直接使用的文件
- `svg/components/figure_up.svg`：目标人物完整轮廓视觉模板。
- `svg/annotated/target_up_debug.svg`：带人工标定关键点的调试版（不可用于正式相机 UI）。
- `fixtures/pose_templates_annotated.json`：目标与 3 种当前姿势的示例关键点，坐标以 `viewBox="40 0 240 455"` 为准。
- `svg/overlays/correction_arc_style.svg`：粉色弧线视觉样式（需要 APP 运行时根据有效方向重新计算）。
- `fixtures/correction_arc_parameters.json`：动态弧线参数及安全隐藏规则。
- `fixtures/pose_guidance_stream_mock.json`：模拟联调帧序列，**不是 AI 检测输出**。
- `docs/PoseGuidanceContract.kt`：Kotlin 接口建议，不是现有代码。
- `preview/*_debug.png`：关键点与轮廓位置关系检查图。

## 最关键的限制
**人工关键点坐标只是用于 APP UI 的示意标定，并非已验证的人体解剖关键点。** 目标轮廓是美术风格化的人物，手部、肩肘处可能与实际姿态模型定义存在偏差。AI 同学应选择实际关键点模型，并逐点核对、调整这些坐标，不能直接用于生产姿势评分。

### 当前与目标的区别
- 目标：静态 SVG 可以作为视觉模板，随画面中目标人物框整体缩放/移动。
- 当前：若有分割掩码，提取并平滑边界生成**真人实时外轮廓**；若只有关键点，只能生成**参数化示意轮廓**，不要声称贴合衣服和头发。
- 纠错：只在 AI 提供有效关节纠错方向时绘制粉色弧线；不能从静态模板自行推断纠错正确性。

### 坐标转换
1. v8 模板 SVG 使用绝对 viewBox 坐标 `[40,0,240,455]`。
2. 关键点 JSON 与 SVG 共用该坐标系，不是归一化坐标；若需归一化，`u=(x-40)/240`，`v=y/455`。
3. 真实相机坐标 → 预览显示坐标须处理旋转、裁切（centerCrop/fit）、缩放、镜像、人物框配准；前置摄像头镜像只能执行一次。
4. 目标和当前轮廓必须经过相同的显示坐标转换；不同人或场景变化时清空旧纠错。

### 运行时状态
`TARGET_VISIBLE → ADJUSTING → VERIFYING → ALIGNED`，另有 `TRACKING_LOST`。这只是 UI 协议建议，不是现有 AI 仓库的真实姿势状态机。不能用构图 `READY` 代替姿势 `ALIGNED`。验证中保持白色；只有独立姿势验证通过才显示绿色。

### Android 开发建议
Compose Canvas 绘制实时分割轮廓、动态弧线；SVG 可用于目标姿势模板。弧线使用旋转中心、起始角、扫角、半径、方向置信度等参数生成，所有几何均以当前帧为准。动画仅可平滑视觉变化，不可推动状态变化。

### 分工
- 设计：目标轮廓、颜色、弧线与状态视觉规范。
- AI：人体关键点、分割轮廓（若追求真实外边界）、有效纠错方向、姿势验证与置信度。
- APP：坐标映射、绘制、时序滤波、状态切换、检测丢失与镜像处理。

### 验收
1. 用 `*_debug.png` 核对每个关键点是否落在相应的视觉关节附近。
2. 人物静止时不能因为动画计时自动变绿。
3. 人物离开画面/遮挡时立刻停止显示错误方向。
4. 纠错弧线不应遮挡主要人体轮廓。
5. 所有正式引导 SVG 不包含操作提示文字；调试图与交接文档可包含标注。
